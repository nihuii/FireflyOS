## 复用等级

**可直接参考。** 固定容量、显式资源冲突和快照式状态是重启项目应保留的约束；具体事件集合和服务装配应按小批次功能重新建立。

## 模块定位

核心运行时不直接控制屏幕、I²C、BLE 或文件系统。它提供跨任务通信、系统状态快照、资源互斥、生命周期和应用能力检查，是上层服务之间的窄接口。

## 职责与边界

- `EventBus`：跨任务传递小型 `SystemEvent`，容量固定为 16。
- `StateStore`：在临界区内维护电量、时间、休眠和手机连接状态，并用 revision 驱动 UI 去重。
- `ResourceGovernor`：用位图表达音频播放、录音、Wi-Fi 传输、OTA、SD 写和高频运动采样之间的冲突。
- `SystemLifecycle`：限制 Booting、Locked、Active、Glance、Sleeping、Updating、Error 之间的转换。
- `AppManager` / `AppRegistry`：静态注册应用，按能力和资源条件打开、关闭页面。
- `CapabilityRegistry` / `HardwareCapabilities`：区分功能是否存在、硬件是否探测成功以及具体失败原因。

核心对象只保护自己的状态；它不会自动让外部硬件驱动变得线程安全。共享 I²C、SPI、音频和 SD 仍需单独所有者。

## 数据流与线程边界

```text
后台服务/硬件回调
    │ post(SystemEvent)
    ▼
EventBus（16 项固定队列）
    │ UI 主循环 take()
    ▼
StateStore / 服务快照更新
    │ snapshot + revision
    ▼
UI Shell 刷新
```

生产者不得在后台回调中直接调用 LVGL。队列满时 `post()` 失败并增加 `droppedCount()`；调用者必须把丢弃计数纳入诊断，而不是假定消息永不丢失。

## 关键接口

| 类型 | 关键约束 | 推荐用途 |
|---|---|---|
| `EventBus` | `kCapacity = 16`，环形数组，临界区保护 | 后台到 UI 的小事件 |
| `StateStore` | 复制快照、revision 单调变化 | UI 只读系统状态 |
| `ResourceGovernor` | 固定资源枚举和冲突掩码 | 拒绝同时录音、OTA、传输等组合 |
| `SystemLifecycle` | 只允许显式状态转换 | BOOT、锁屏、一瞥、睡眠和更新 |
| `HardwareCapabilities` | 记录每个硬件的 `HardwareStatus` | 空状态和诊断页 |

## 精选代码

来源：`libraries/FireflyOS/src/firefly/core/EventBus.h`，符号 `EventBus`。

```cpp
class EventBus {
public:
    static constexpr uint8_t kCapacity = 16;

    bool post(const SystemEvent & event);
    bool take(SystemEvent & event);
    uint8_t size() const;
    uint8_t peakSize() const;
    uint16_t droppedCount() const;

private:
    mutable portMUX_TYPE mux_ = portMUX_INITIALIZER_UNLOCKED;
    SystemEvent events_[kCapacity]{};
    uint8_t head_ = 0;
    uint8_t tail_ = 0;
    uint8_t count_ = 0;
};
```

这段实现值得保留的是“固定容量 + 可观测丢弃”，不是容量数值本身。重启后若事件载荷变大，应先缩小事件而不是直接扩大队列。

## 验证边界

自动测试能检查固定容量、事件消费边界和状态模型契约；不能证明 FreeRTOS 调度压力下无丢事件，也不能证明硬件驱动遵守同一所有权。相关真机项目仍为 `PENDING`。

## 已知问题

- 单个 `EventBus` 容量只有 16，高频来源若没有合并或节流会丢事件。
- `portMUX_TYPE` 只能保护短临界区；禁止在锁内做 I/O、动态分配或 LVGL 操作。
- `HardwareCapabilities` 是状态记录器，不是自动恢复器；探测失败后的重试策略必须由服务定义。

## 基于 main 的复用步骤

1. 先引入最小 `SystemEvent`、`EventBus` 和丢弃诊断，不接任何后台硬件任务。
2. 在 UI 主循环中消费事件并验证 LVGL 单线程规则。
3. 再加入 `StateStore` 快照和 revision 去重。
4. 每引入一种重资源功能时再扩展 `ResourceKind`，为冲突组合写测试。
5. 真机压力测试队列峰值和丢弃计数后，才允许增加后台事件来源。
