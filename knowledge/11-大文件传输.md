# 大文件传输

## 目标

当前 main 没有大文件传输实现。旧方案的可复用核心是：BLE 只协商临时会话，文件经短命私网通道写入受管临时文件，长度和 SHA-256 一致后才原子提交。

## 推荐边界

- 控制面携带 request ID、受管路径、声明长度、摘要和一次性 token。
- 数据面限制私网端点、header、正文长度、超时和最大文件；服务端不信任手机预检。
- 目标只允许白名单目录，拒绝 `..`、特殊分隔符和最终名以 `.part` 结尾。
- 传输先获得 SD 与 Wi-Fi 租约，并与音频、OTA 和低电策略互斥。
- 网络回调只更新有界进度快照，不接触 LVGL。
- 失败、取消、超时、重启和拔卡都关闭句柄、删除临时文件并释放租约。

## 最小实现

1. 先定义路径校验、存储租约和临时文件提交接口。
2. 加入 request ID、长度、摘要、取消和全部清理分支。
3. 用真机小文件验证 SD 独占、空间检查、拔卡和原子改名。
4. 接入同局域网 HTTP 与一次性认证。
5. 最后增加 SoftAP 回退和最大文件长传测试。

## 主要风险

轮询过密会把 Wi-Fi、SD、音频和 OTA 绑成并发故障面；multipart 和 header 必须在 transport 层限长；一次性 token 不能升级成长期凭据。在摘要确认前，主题、音乐和更新模块都不能看到最终文件。
