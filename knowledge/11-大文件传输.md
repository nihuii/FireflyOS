- 固定提交：`e4fb0d1ff71bcc0330b507fa90c653be9929e611`

## 复用等级

**可直接参考协议边界，服务实现需重构后复用。** 请求 ID、一次性 token、声明长度、SHA-256、`.part` 文件和原子提交是可保留的核心；HTTP、SD、Wi-Fi、BLE 和 UI 生命周期不应继续集中在一个巨型集成层。

## 模块定位

BLE 只承载小型控制帧。大文件先经已认证 BLE 帧协商临时会话，再通过同局域网或设备 SoftAP 上的短命 HTTP 端点传输。目标仅限 FireflyOS 托管目录，传输完成且长度、摘要均匹配后才把 `.part` 提交为最终文件。

## 职责与边界

- BLE 控制面：请求、就绪状态、取消和结果通知。
- `BulkTransferService`：会话状态机、请求 ID、token、超时、冲突门控和摘要核验。
- `BulkTransferStorage`：创建临时文件、追加、关闭、提交和清理。
- HTTP transport：校验认证头和固定字段，只把正文分块交给服务。
- Android uploader：预检路径/长度/摘要，限定私网 HTTP `/upload`，使用固定长度流。
- SD、音频、OTA：以显式租约或 busy 标志参与互斥，不靠“通常不会同时发生”。

最大文件 64 MiB；目标路径必须位于 `Themes`、`Pictures`、`Music` 或 `Updates` 的受管一级目录，禁止 `..`、特殊字符和 `.part` 结尾。

## 数据流与线程边界

```text
Android 计算 size + SHA-256
       |
认证 BLE Request(request_id/path/size/hash)
       |
设备预检 电量/Wi-Fi/SD/空间/音频/OTA -> Ready(endpoint/token/expiry)
       |
Android 私网 HTTP 固定长度上传 -> 设备分块写 .part + 增量 SHA-256
       |
长度和摘要一致 -> close -> 原子 rename -> Completed
失败/取消/超时 -> close/remove .part -> 释放 SD/Wi-Fi/功耗会话
```

网络回调不能接触 LVGL。进度通过有界快照或事件交给 UI。取消需要同时中止 Android socket、设备 HTTP 会话和存储写入，并以请求 ID 避免旧回调污染新会话。

## 关键接口

| 项目 | 固定边界 |
|---|---:|
| 最大文件 | 64 MiB |
| SD 保留空间 | 4,096 B |
| 网络等待 / 无进展 | 15 s / 5 min |
| 会话绝对上限 | 15 min |
| token | 16 B 随机值，传输为 32 位十六进制 |
| endpoint | 最多 95 B |
| 受管路径 | 最多 191 B |
| Android 连接/读取超时 | 各 15 s |

## 验证边界

契约测试可覆盖路径、大小、哈希、token、重复回调、取消和超时规则；不能证明真实 SD 卡写入稳定性、手机网络绑定、SoftAP 切换、64 MiB 长传功耗、断连清理或原子重命名在所有卡上的行为。大文件传输正式真机项仍为 `PENDING`。

## 已知问题

- 旧实现的 Bulk task 每 5ms 轮询，和 Wi-Fi、SD、音频、OTA 形成高耦合并发面。
- multipart 边界解析、正文长度和 header 上限必须由 transport 严格限制，不能只信 Android 客户端。
- token 只用于一次临时本地传输，不是长期账号凭据；会话结束、取消或超时后必须失效。
- `.part` 清理要覆盖启动失败、网络异常、哈希失败、取消、重启和存储拔出。
- 在校验成功之前，主题、音乐或 OTA 包都不能被业务层看到为正式文件。

## 基于 main 的复用步骤

1. 先定义受管路径规范、存储租约和 `.part` 提交接口，用本地伪 transport 验证。
2. 加入请求 ID、长度、SHA-256 和取消状态机，测试所有清理分支。
3. 在真机上只用固定小文件验证 SD 独占、空间检查、原子提交与拔卡失败。
4. 接入同局域网 HTTP；确认私网地址、token、超时和 Android 网络绑定。
5. 再加入 SoftAP 回退与 64 MiB 边界测试，并测量功耗、温升和长传稳定性。
6. 只有前述门槛通过后，才让主题、音乐和 OTA 消费已提交文件。
