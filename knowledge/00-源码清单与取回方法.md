# 源码清单与取回方法

## 当前基线

唯一开发基线是 `main@fab5509`。日常开发先查看当前工作区，不把旧分支或历史总装当作可直接合并的来源。

## 当前源码入口

| 范围 | 路径 | 内容 |
|---|---|---|
| 主固件 | `Firefly/` | Arduino 入口、显示、交互、状态和内置资源 |
| 核心库 | `libraries/FireflyOS/src/firefly/core/` | 事件、状态、生命周期、应用和资源治理 |
| HAL | `libraries/FireflyOS/src/firefly/hal/` | I²C 管理、受锁寄存器设备和旧板适配 |
| UI | `libraries/FireflyOS/src/firefly/ui/` | Shell、导航、主题、组件和系统页面 |
| 测试 | `tests/` | Python 合约和核心测试固件 |
| 工具 | `tools/` | 构建、字体、UI 预览和验证脚本 |
| 设计资料 | `docs/`、`image/ui_mockups/` | 执行计划、模块说明和视觉基线 |

用 `rg --files <path>` 查看清单，用 `rg -n <symbol> <path>` 定位符号。只有文件确实存在于当前工作区时，才能描述为当前能力。

## 本地历史参考

计划 3～6 的旧软件快照可在本机 Git 对象 `e4fb0d1ff71bcc0330b507fa90c653be9929e611` 中查阅，但远端不保证能够重新下载。

检查对象是否存在：

```powershell
git cat-file -e "e4fb0d1^{commit}"
```

查看历史文件：

```powershell
git show "e4fb0d1:libraries/FireflyOS/src/firefly/services/WifiService.h"
```

列出历史清单：

```powershell
git ls-tree -r --name-only e4fb0d1
```

历史内容只用于理解接口、状态机和失败路径。需要采用时重新设计最小接口，手工移植少量逻辑，并为当前基线重新建立测试和真机记录；不要直接覆盖当前同名文件。

## 证据边界

知识库校验只证明文档结构、相对路径规则和内部链接有效。它不证明源码已进入主程序，也不证明烧录、触摸、传感器、功耗、SD、音频、无线或 OTA 在真机通过。
