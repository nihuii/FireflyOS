## 复用等级

**需要重构后复用。** 受管路径、单一存储入口、打开句柄计数以及 Bulk/OTA 独占会话是正确边界；`StorageService` 已增长为大型多职责类，重启时应按内部配置、普通 SD、独占 SD 三部分收缩接口。

## 模块定位

存储域同时管理 NVS/LittleFS 中的小型配置和 SD_MMC 中的用户文件。所有应用应通过 `StorageService` 访问 `/FireflyOS` 受管目录，不能直接保存 `fs::FS*` 或绕过拔卡监测。

## 职责与边界

- `SdCardDevice`：固定 1-bit SD_MMC 引脚，挂载、容量、受管目录、连续失败和拔卡事件。
- `StorageService`：设置、闹钟、活动、配对、Wi-Fi、主题缓存持久化；统一包装 SD 文件操作。
- `FileScanService`：每页最多 32 项，每 tick 处理 4 项，扫描结果通过事件交给 UI。
- `FilesApp`：只展示页面和提交操作，不直接遍历文件系统。
- Bulk 和 OTA 必须先获取独占会话；存在普通打开句柄时拒绝开始。

## 数据流与线程边界

```text
应用/服务 ── openManaged/readManaged/writeManaged ── StorageService
                                                     │ mutex + handle count
                                                     ▼
                                                SdCardDevice / SD_MMC

BulkTransfer 或 OTA ── begin...SdSession
      └─ 仅当 normal_sd_handles_ == 0 且另一独占会话未运行时成功
```

UI 文件列表不应在 LVGL 回调里完成整个目录扫描。`FileScanService` 分批读取，并通过 generation 丢弃过期结果。

## 关键接口

| 类型 | 固定边界 |
|---|---|
| `SdCardDevice` | 路径最长 160；受管根固定 `/FireflyOS` |
| `FileScanPage` | 32 项，每项名称 48 字节 |
| `FileScanService` | `kEntriesPerTick = 4` |
| `PairingRecord` | 16 字节 token、33 字节手机名 |
| `StorageService` | 普通、Bulk、OTA 三类 SD 所有权 |

受管顶层目录为 `Music`、`Recordings`、`Pictures`、`Themes`、`Updates`、`Backups`、`Logs`。路径不得包含反斜杠、冒号、空组件或向上跳转。

```cpp
bool StorageService::beginBulkSdSession() {
    if(!sd_mutex_ || xSemaphoreTake(sd_mutex_, pdMS_TO_TICKS(50)) != pdTRUE) {
        return false;
    }
    const bool available = !bulk_sd_session_ && !ota_sd_session_ &&
        normal_sd_handles_ == 0 &&
        sd_filesystem_ && sd_device_ && sd_device_->validateSession();
    if(available) bulk_sd_session_ = true;
    xSemaphoreGive(sd_mutex_);
    return available;
}
```

这一模式应保留：独占操作不是“更高级的锁”，而是必须等所有普通句柄关闭后才进入的状态。

## 验证边界

合约测试覆盖受管路径、单一入口、文件分页和拔卡事件传播；不能证明具体 SD 卡兼容性、热拔插稳定、长时间写入、断电一致性或 FAT 损坏恢复。相关真机项目仍为 `PENDING`。

## 已知问题

- `StorageService` 同时承担 NVS、LittleFS、SD、配对、Wi-Fi、主题和独占会话，接口面过大。
- `fs::File` 仍会传给客户端；客户端必须使用 `closeManaged`，否则 `normal_sd_handles_` 无法归零。
- 递归恢复出厂删除深度限制为 8；新目录层级不能在没有测试的情况下突破该限制。
- 连续失败监测只能推断卡已移除，不能替代硬件卡检测引脚。

## 基于 main 的复用步骤

1. 先引入内部设置存储，建立 schema 和迁移测试，不接 SD。
2. 单独接入 `SdCardDevice` 和受管目录，在真机验证挂载、读写、拔卡和不同容量卡。
3. 引入最小 `ManagedFile` 或 RAII 句柄，避免调用方忘记归还计数。
4. 加入分页扫描，确认 UI 主循环无长阻塞。
5. 最后加入 Bulk/OTA 独占租约，并用打开普通文件时拒绝独占的测试锁定边界。
