# 存储、文件与 SD 卡

## 目标

当前 main 尚无统一存储服务；根目录示例只用于板级探测。新实现应把内部设置和 SD 用户文件分开，并让所有 SD 操作经过单一受管入口。

## 推荐边界

- 内部设置使用版本化 schema 和显式迁移，不在启动失败时自动格式化。
- SD 仅开放 `/FireflyOS` 下的白名单目录，拒绝绝对路径、反斜杠、冒号和 `..`。
- 普通文件句柄必须可计数并自动归还；Bulk 与 OTA 只能在普通句柄归零后取得独占租约。
- UI 不同步遍历大目录；扫描按固定页和固定 tick 批量返回，generation 用于丢弃过期结果。
- 拔卡和连续 I/O 失败转换为明确状态，不让应用继续持有底层文件系统指针。

## 最小实现

1. 先完成内部设置 schema、迁移和只读恢复。
2. 单独挂载 SD，验证受管目录、读写、拔卡和多容量卡。
3. 引入自动关闭的受管文件句柄。
4. 加入分页扫描并确认 UI 主循环无长阻塞。
5. 最后增加 Bulk/OTA 独占租约和冲突测试。

## 主要风险

把 NVS、FFat、SD、配对和主题集中进巨型服务会扩大故障面；裸 `fs::File` 易造成句柄计数不归零；软件失败次数不能完全替代硬件卡检测。自动路径测试不能证明 FAT 损坏、断电一致性和真实热拔插恢复。
