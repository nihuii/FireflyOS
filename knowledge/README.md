# FireflyOS 旧实现参考知识库

本知识库服务于基于 `main@351dff7` 的重启开发。该提交是 `8e79cc2` UI Shell 的直接后继，包含当前 main 的文档整理；参考源码固定为 `codex/wifi-weather-ota@e4fb0d1ff71bcc0330b507fa90c653be9929e611`，即计划 1～6 的最终软件实现快照。

这里记录的是可借鉴的边界、接口、状态机和失败经验，不是可以整批合并的新基线。计划 1～6 的正式真机验收仍为 `PENDING`；Python、Android 单元测试、Debug APK 和固件编译不得写成真机通过。

## 快速使用

1. 先读 [源码清单与取回方法](00-源码清单与取回方法.md)，确认来源提交和取回命令。
2. 按功能阅读下表中的模块卡片。
3. 查看模块的“复用等级”和“已知问题”，再决定是否取回原始文件。
4. 按 [主程序集成与后续复用顺序](14-主程序集成与后续复用顺序.md) 小批次重新引入，完成当批真机门槛后再继续。
5. 运行 `python knowledge/validate_knowledge.py` 检查知识库结构和 Git 来源引用。

## 已确认的高风险问题

- `UI Shell`：`status_drag_cb` 只绑定面板父对象、顶部状态栏和窄把手；全屏子页面会截获大部分触摸，导致面板无法稳定上滑返回。
- `共享 I²C`：触摸通过 `touch.h` 直接调用 `Wire`，而 PMU、RTC、QMI8658 由后台任务经共享锁访问，同一总线可能发生跨核竞态。
- `BOOT/息屏`：锁屏短按进入一瞥、约两秒后黑屏是旧状态机的既定转换，不能单独视为崩溃证据。
- `烧录链路`：上传中的 pySerial `PermissionError` 发生在 ROM/stub 阶段，与尚未运行的应用逻辑分开诊断。
- `Release`：仓库外生产公钥缺失时必须失败闭锁；知识库不会保存或伪造生产密钥。

## 知识库能证明什么

校验器成功只表示文档齐全、链接有效、固定提交中的源码路径可取回。它不能证明固件可烧录、触摸正常、功耗达标、BLE/Wi-Fi 真机稳定或 OTA 可以发布。

## 维护规则

- 引用旧实现时始终保留 `e4fb0d1`，不要把后续同名文件误认为同一实现。
- 新项目真正采用代码后，应在新代码旁建立自己的测试和真机记录，不修改本知识库中的历史结论。
- 知识库只保存精选片段；完整内容始终通过 Git 对象数据库取回。
