# FireflyOS 轻量知识库

当前开发基线是 `main@fab5509`。本知识库只提供模块边界、状态机和失败经验，用于写新代码前快速确定思路；它不是旧版本恢复清单，也不表示计划 3～6 已进入当前主程序。

## 使用方法

1. 先读 [源码导航](00-源码清单与取回方法.md)，区分当前源码和本地历史参考。
2. 每次只打开当前功能对应的一张模块卡片。
3. 优先采用卡片中的边界和失败策略，不整段复制旧实现。
4. 按 [渐进集成顺序](14-主程序集成与后续复用顺序.md) 小批开发。
5. 运行 `python knowledge/validate_knowledge.py` 检查结构和路径。

具体任务、自动验证和真机门槛统一在 `docs/执行计划/00-总体执行路线图.md` 中维护；模块卡片不重复保存施工步骤或完成状态。

## 当前事实

- 当前固件包含核心运行时、HAL 基础、UI Shell、锁屏、桌面、系统面板和覆盖层。
- 当前源码的系统面板已实现后代事件冒泡、方向仲裁、按钮抑制和滑杆状态恢复；自动测试与构建不能替代目标板矩阵。
- 当前主程序还包含 RTC 读写、电池/充电、闹钟调度/UI/持久化和 `Qmi8658ControlAdapter`；独立时间、闹钟、电源和运动服务闭环仍未完成。
- Activity、Weather、Music、Recorder、Files 目前只有 UI 路由或占位，不能描述为已实现应用。
- Android、BLE、存储媒体、Wi-Fi、传输和 OTA 卡片主要来自本地历史对象，只作思路参考。
- 自动编译、Python 测试、Android 测试或 APK 生成都不能替代真机验收。
- 未重新执行的硬件项目保持未验证，不沿用旧计划的通过结论。

## 全局约束

- 固定使用 LVGL 8.3.11；LVGL 只能由 UI 主循环访问。
- UI 适配 410×502 圆角屏，主要触摸目标至少 48px，正式界面先做预览。
- 事件、队列、缓存、导航和网络输入使用固定容量。
- 触摸、RTC、PMU、IMU 必须共享同一个 I²C 所有权边界。
- SD、音频、Wi-Fi 和 OTA 使用显式租约或冲突门控。
- 手表本地能力优先，手机和网络只能增强，不能成为基础功能前置条件。
- 生产密钥、私有端点和用户凭据不得写入知识库。

## 首要风险

1. 系统面板上滑返回的软件修复已进入当前 main，但背景、卡片、按钮、滑杆和通知项起手的完整真机矩阵尚未执行。
2. 触摸直接访问 `Wire` 与后台设备访问同一 I²C，旧方案存在跨核竞态。
3. BOOT、一瞥和息屏状态转换必须用日志区分设计行为与崩溃。
4. 烧录阶段的串口异常发生在应用启动前时，应独立检查 USB、供电、驱动和端口占用。
