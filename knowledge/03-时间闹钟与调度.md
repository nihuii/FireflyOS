## 复用等级

**需要重构后复用。** 时间快照、闹钟固定槽位、同一分钟去重以及响铃期间延迟网络校时值得保留；RTC 访问必须与触摸、PMU、IMU 一起重新定义 I²C 所有权。

## 模块定位

`TimeService` 统一维护当前 epoch、RTC 读写和网络校时，`AlarmService` 只负责固定闹钟配置与触发判定。时钟应用负责秒表、倒计时和页面状态，但不应直接操作 RTC 或网络。

## 职责与边界

- `TimeService`：启动时从 `ClockDevice` 读取时间，提供线程安全快照，处理本地设置和 NTP 结果。
- `AlarmService`：固定 2 个闹钟槽、4 个内置铃声，按星期掩码判断触发。
- `ClockApp`：时钟、闹钟、倒计时、秒表交互；页面关闭不能阻塞核心计时。
- `FireflyAlarm.cpp`：旧主程序中的响铃装配和音频接入，重启时应继续下沉到服务层。

时间服务不得调用 LVGL。UI 只读取 `TimeSnapshot` 或 `SystemState.time`，并由 UI 主循环更新时间标签。

## 数据流与线程边界

```text
RTC ── reloadRtc() ──┐
                     ├─ TimeService（互斥快照）─→ UI/AlarmService
NTP ─ applyNetworkTime┘
        │ 响铃中
        └─ deferred_network_epoch_ ── 响铃结束后 flush

AlarmService.publishTrigger
        └─ EventBus Critical event ──→ UI 主循环启动覆盖层和音频
```

网络校时若与响铃同时发生，不应在响铃过程中突然跳变系统时间。原实现把网络 epoch 暂存，响铃结束后再写 RTC。

## 精选代码

来源：`libraries/FireflyOS/src/firefly/services/TimeService.cpp`，符号 `applyNetworkTime`。

```cpp
bool TimeService::applyNetworkTime(int64_t epoch_seconds,
                                   bool alarm_ringing) {
    TimeRecursiveLock lock(mutex_);
    if(epoch_seconds <= 0) return false;
    const int64_t difference = current_.valid
        ? epoch_seconds - current_.epoch_seconds : epoch_seconds;
    if(current_.valid && difference >= -2 && difference <= 2) {
        network_sync_pending_ = false;
        deferred_network_epoch_ = 0;
        return true;
    }
    if(alarm_ringing) {
        deferred_network_epoch_ = epoch_seconds;
        network_sync_pending_ = true;
        return true;
    }
    return setLocalTime(epoch_seconds);
}
```

这里的关键点是“响铃优先”和“两秒以内不写 RTC”。重启实现还应记录 NTP 来源、时区版本和最近成功同步时间。

来源：`libraries/FireflyOS/src/firefly/services/AlarmService.cpp`，符号 `publishTrigger`。

```cpp
bool AlarmService::publishTrigger(int64_t now,
                                  uint32_t timestamp_ms,
                                  EventBus & events) {
    uint8_t slot = 0;
    if(!findDueSlot(now, slot)) return false;
    const SystemEvent event(EventType::AlarmTriggered, slot, timestamp_ms,
                            EventPriority::Critical);
    if(!events.post(event)) return false;
    last_trigger_minute_[slot] = now / 60;
    return true;
}
```

只有事件成功进入队列后才更新去重标记，避免队列满时静默丢失本次闹钟。临界闹钟事件仍需要队列容量和真机压力验证。

来源：`libraries/FireflyOS/src/firefly/services/AlarmService.h`，符号 `Alarm`。

## 验证边界

自动测试覆盖闹钟事件非阻塞、铃声资源边界和事件消费；不能证明 RTC 掉电保持、跨日/夏令时行为、响铃音量、NTP 实网可用或唤醒可靠。相关真机项目均为 `PENDING`。

## 已知问题

- `TimeService` 用 epoch 表达当前时间，但时区和夏令时策略分散在主程序环境配置中。
- RTC 与其他设备共享 I²C；服务互斥只保护时间状态，不能保护物理总线。
- 两个闹钟槽是当前产品约束，扩容前应先定义持久化迁移，而不是只增大数组。
- 响铃覆盖层、音频资源和时间判定跨越多个旧文件，重启时应建立单一 `AlarmCoordinator` 或等价装配边界。

## 基于 main 的复用步骤

1. 先实现纯内存 `TimeService` 和假 `ClockDevice`，验证快照、手动校时和跨日。
2. 接入 RTC 时统一走共享 I²C 所有者，并在真机连续读取中确认触摸不受影响。
3. 加入单个闹钟槽，验证事件成功入队后才去重。
4. 接入响铃音频和覆盖层，验证关闭、贪睡、BOOT 操作均释放音频。
5. 最后加入 NTP，覆盖响铃期间延迟校时和断网恢复，再关闭该阶段真机门槛。
