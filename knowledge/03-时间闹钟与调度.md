# 时间闹钟与调度

## 目标

当前 main 已有 RTC 初始化/读写、系统时间同步、固定槽位闹钟调度、闹钟 UI 和 Preferences 持久化，但这些仍是主程序级装配。独立 `TimeService`、`AlarmService` 和时钟应用只存在于本地历史对象参考；新实现应在保留现有行为的同时，让 RTC、闹钟判定、UI 显示和网络校时彼此解耦。

## 推荐边界

- 时间服务拥有 epoch 和 RTC 快照，UI 不直接操作 RTC。
- 闹钟使用固定槽位、星期掩码和“同一分钟只触发一次”记录。
- 只有触发事件成功入队后才更新去重状态，避免队列满时静默漏响。
- 网络时间差很小时不重复写 RTC；响铃期间延后校时。
- RTC 访问必须经过与触摸、PMU、IMU 相同的 I²C 所有者。
- 倒计时和秒表使用单调时钟，不依赖系统 epoch 跳变。

## 最小实现

1. 先用内存时钟实现快照、手动校时和跨日测试。
2. 把现有 RTC 调用迁入服务，并在持续触摸时验证总线稳定。
3. 先用单个闹钟槽验证可靠事件投递，再迁移现有固定槽位与持久化。
4. 保留现有响铃覆盖层和关闭路径，再加入贪睡与音频会话。
5. 最后加入 NTP、时区和响铃期间延迟校时。

## 主要风险

时区和夏令时策略容易散落；RTC 状态锁不能保护物理 I²C；响铃判定、音频和覆盖层跨多个文件会导致清理不完整。编译通过不能证明 RTC 掉电保持、跨日、唤醒或真实响铃可靠。
