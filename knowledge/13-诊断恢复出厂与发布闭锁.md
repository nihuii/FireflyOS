# 诊断、恢复出厂与发布闭锁

## 目标

当前 main 有基础能力注册、Gate A 串口诊断和构建入口；有界诊断服务、恢复出厂状态机和 Release 安全闭锁属于本地历史对象参考。新实现应让故障可观测，同时避免诊断本身改变系统时序。

## 推荐边界

- 常态指标写入固定 RAM 环形缓冲，只在用户操作时导出串口或 SD。
- 能力快照区分未探测、可用、降级和失败原因，不把缺硬件视为整个系统失败。
- 恢复出厂使用 generation、防重复确认、内部清除和可选 SD 二次确认。
- 每个数据所有者实现幂等清理；服务不猜测 NVS 名称和文件路径。
- SD 只清理 FireflyOS 受管白名单，禁止格式化整卡或递归删除盘符根。
- Release 缺少仓库外生产信任锚、固定更新配置或尺寸检查时立即失败且不留发布产物。

## 最小实现

1. 先接入能力快照、事件丢弃和少量 RAM 诊断记录。
2. 为每个真机驱动记录探测结果和失败原因。
3. 建立数据所有权清单，为每个 owner 写幂等清理测试。
4. 加入恢复预览、generation 和内部确认。
5. 真机验证后再增加 SD 二次确认和显式诊断导出。
6. 恢复 OTA 时再启用完整 Release 输入与尺寸闭锁。

## 主要风险

热路径打印和频繁写卡会改变故障表现；部分清理失败后无条件重启会掩盖问题；SD 模糊路径极易误删用户文件；测试公钥不能替代生产信任锚。自动测试只能证明容量与状态迁移，不能证明真实堆水位、任务栈、清理后首启或发布安全。
