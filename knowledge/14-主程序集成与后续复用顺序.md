## 模块定位

本章不是另一个功能模块，而是知识库的入口顺序：规定新项目每批只恢复一个最小闭环，通过真机门槛后再引入下一层。任何自动编译、Python/Android 单测或 APK 生成都只是该批的自动证据，不替代真机结论。

## 职责与边界

- UI 主循环：唯一可访问 LVGL 的上下文，读取服务快照并提交用户命令。
- 后台服务：不持有 LVGL 对象；通过固定队列、事件或快照通信。
- 总线所有者：触摸、RTC、PMU、IMU 必须走同一个 I²C 仲裁策略。
- 存储所有者：SD 访问经单一服务和明确租约，音频、主题、Bulk、OTA 不直接抢占。
- 功耗裁决：所有高功率会话统一经过电源门控。
- 验收记录：每批分别保存自动证据和正式真机证据，未执行即 `PENDING`。

必须继续遵守 LVGL 8.3.11、410×502 圆角安全区、至少 48px 触摸区、正式 UI 先预览、固定容量和独立运行优先。

## 数据流与线程边界

```text
硬件 ISR/驱动 -> 有界事件或设备快照 -> 服务状态机 -> UI 快照
     ^                                  |             |
     |                                  v             v
统一 I²C/SD/音频租约 <- 功耗与冲突门控 <- 命令队列 <- LVGL 主循环
```

建议启动阶段只有 UI 主循环和一个低频服务推进点。只有当耗时 I/O 的真机证据证明必须异步时才新增任务；新增任务必须声明栈、核心、轮询周期、共享对象、锁顺序、退出和恢复出厂暂停语义。

## 关键接口

| 集成契约 | 要求 |
|---|---|
| LVGL | 仅 UI 主循环访问 |
| UI↔服务 | 固定容量命令、事件、快照 |
| I²C | 单一总线管理器；禁止驱动绕过锁直接用 `Wire` |
| SD | 单一受管入口与租约 |
| 电源 | 音频、Wi-Fi、Bulk、OTA 统一门控 |
| 批次完成 | 自动检查 + 对应真机项完成 + 问题回归 |
| 批次失败 | 修在最早责任层，不把补丁堆到总装层 |

## 验证边界

知识库校验只能证明文件齐全、内部链接有效、固定 Git 来源可读取和边界标记存在。它不能证明代码已回到 main，更不能证明烧录、触摸、按键、睡眠、音频、BLE、Wi-Fi、传输或 OTA 正常。计划 1～6 正式真机项全部从 `PENDING` 开始。

## 已知问题

- 状态栏上滑返回缺陷已经定位到事件只绑定面板父对象、顶部栏和 84×6 把手；全屏子页截获了大部分触摸。重做覆盖层手势前不能宣称 UI Shell 真机通过。
- 触摸直接使用 `Wire`，而 RTC、PMU、QMI8658 在另一核心经共享锁访问同一 I²C，总线竞态可表现为卡屏、闪屏或重启。
- BOOT 短按从锁屏进入 glance、约两秒后黑屏是旧状态机既定路径，需用状态日志区分设计行为和崩溃。
- esptool 上传中途的 pySerial `PermissionError` 发生在主应用尚未执行时，应从 USB 线、供电、驱动、端口占用、stub/波特率和 flash 链路独立诊断。
- 旧总装中服务和任务数量远超当前真机证据承载能力；整批移植会重新引入无法归因的问题。

## 基于 main 的复用步骤

1. **批次 A：UI Shell 基线。** 只保留显示、触摸、锁屏、桌面、导航和状态覆盖层；先修覆盖层完整手势接收，再做滑动/按键/反复息屏真机验证。
2. **批次 B：硬件总线与电源。** 建立统一 I²C 所有权，逐个恢复 RTC、PMU、IMU；每加入一个设备就执行长时间触摸和唤醒回归。
3. **批次 C：核心应用。** 依次恢复时钟/闹钟、设置和工具；每次只加一个状态机，不提前接媒体或无线。
4. **批次 D：存储与音频。** 先 SD 单一入口，再播放，最后录音；分别验证拔卡、冲突、WAV 收尾和功耗。
5. **批次 E：BLE 与 Android。** 从 Hello/Pair/Ack 最小协议开始，真机通过后逐类恢复通知、设置、天气和媒体命令。
6. **批次 F：按需 Wi-Fi。** 先 NTP，再配网确认、手机天气、直连天气；逐项验证断网与低电门控。
7. **批次 G：Bulk 与 OTA。** 先传输临时文件，再双分区 OTA、首启回滚和 Release 闭锁；在此前不得创建 RC。
8. 每批发生问题时回退到最近真机通过的批次，在最早责任模块修复并复测；只有用户授权后才提交、合并或推送。
