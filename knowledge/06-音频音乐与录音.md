# 音频、音乐与录音

## 目标

当前 main 保留板级 ES8311 示例和闹钟装配，没有统一音频服务。新实现应让音乐、录音、闹钟和系统提示音共享一个硬件入口，并为抢占和文件收尾定义确定结果。

## 推荐边界

- 音频用途优先级固定为 `Alarm > Recorder > System > Music`。
- UI 只请求会话；Codec、I²S、功放和 SD 由音频服务管理。
- 播放和录音每次处理固定字节数，禁止在 UI 回调中处理整文件。
- 录音先写受管 `.tmp`，停止时回填 WAV 头、关闭，再原子改名。
- 抢占或低电停止也必须尝试收尾；失败时保留可恢复临时文件。
- 板级引脚和采样参数必须用探针真机确认。

## 最小实现

1. 用纯内存测试锁定用途仲裁和抢占结果。
2. 通过独立探针验证 Codec、I²S、喇叭、麦克风和功放。
3. 先加入固定 PCM 提示音，再加入可靠停止的闹钟循环。
4. 接入 WAV 播放及坏文件、拔卡路径。
5. 最后加入录音、WAV 收尾、重启恢复和长时间真机测试。

## 主要风险

单一当前用途不足以自动恢复被抢占会话；录音头写失败不能直接删除数据；音频与 SD、电源、闹钟相互依赖，必须有统一清理顺序。AudioProbe 编译成功不表示能听到声音或录到有效波形。
