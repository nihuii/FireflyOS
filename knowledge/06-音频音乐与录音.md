## 复用等级

**需要重构后复用。** 音频用途优先级、录音临时文件和 WAV 头收尾值得保留；真实 ES8311、I²S 引脚、麦克风输入、功放和 SD 写入必须逐项真机验证。

## 模块定位

`AudioService` 是音乐、录音、闹钟和系统提示音的唯一硬件入口。应用只请求用途明确的音频会话，仲裁器决定是否允许抢占；存储仍由 `StorageService` 管理。

## 职责与边界

- `Es8311Device`：通过受锁 I²C 寄存器适配器配置 codec、音量、静音和休眠。
- `AudioSessionArbiter`：优先级 `Alarm > Recorder > System > Music`。
- `AudioService`：安装 I²S、播放 PCM/WAV、录制、WAV 解析与头部修复。
- `MusicApp`：固定队列、进度、暂停/继续和本地媒体命令。
- `RecorderApp`：生成临时文件名，停止时完成 WAV 头并改名。

LVGL 页面不得直接写 I²S 或 SD。闹钟抢占录音时，必须先尝试完成录音头；即使失败也要关闭硬件和释放仲裁状态。

## 数据流与线程边界

```text
Music / Recorder / Alarm
        │ request AudioUse
        ▼
AudioSessionArbiter ── priority check ── AudioService
                                            ├─ ES8311 + I²S
                                            └─ StorageService managed file
```

`service()` 和 `serviceRecording(max_bytes)` 采用有界批次，避免一次处理整个文件阻塞 UI。

## 关键接口

| 类型 | 固定边界 |
|---|---|
| `AudioUse` | None、System、Music、Recorder、Alarm |
| `AudioService` | WAV 头固定 44 字节 |
| I²S 引脚 | MCLK 41、BCLK 45、WS 40、DOUT 42、DIN 16、AMP 46 |
| 录音服务 | 默认每次最多处理 512 字节 |
| 闹钟铃声 | 由 `AlarmService` 提供固定内置资源 |

## 精选代码

来源：`libraries/FireflyOS/src/firefly/services/AudioService.cpp`，符号 `AudioSessionArbiter::acquire`。

```cpp
bool AudioSessionArbiter::acquire(AudioUse requested) {
    if(requested == AudioUse::None) return false;
    if(current_ == AudioUse::None || current_ == requested ||
       priority(requested) > priority(current_)) {
        current_ = requested;
        return true;
    }
    return false;
}

uint8_t AudioSessionArbiter::priority(AudioUse use) {
    switch(use) {
        case AudioUse::Alarm: return 4;
        case AudioUse::Recorder: return 3;
        case AudioUse::System: return 2;
        case AudioUse::Music: return 1;
        default: return 0;
    }
}
```

来源：`libraries/FireflyOS/src/firefly/services/AudioService.cpp`，符号 `finishRecording`。

```cpp
bool AudioService::finishRecording() {
    if(!recording_file_) return true;
    uint8_t header[kWavHeaderBytes]{};
    const bool header_ready = buildWavHeader(
        header, sizeof(header), recording_data_bytes_, recording_sample_rate_, 1);
    const bool seek_ready = header_ready && recording_storage_ &&
        recording_storage_->seekManaged(recording_file_, 0);
    const bool write_ready = seek_ready &&
        recording_storage_->writeManaged(recording_file_, header,
                                         sizeof(header)) == sizeof(header);
    // 原实现随后关闭文件并清理会话
    return write_ready;
}
```

上段为关键流程提炼，完整函数应从固定提交取回。重启实现应把“写头、关闭、临时文件改名”做成一个可测试的事务结果，而不是只返回布尔值。

## 验证边界

自动测试覆盖仲裁、路径、WAV 头和临时文件清理契约；编译 AudioProbe 不等于听到声音或录到有效波形。功放、喇叭、麦克风、采样率、SD 连续写和闹钟抢占均为 `PENDING` 真机项。

## 已知问题

- `AudioSessionArbiter` 只记录一个当前用途，没有完整的暂停栈；抢占后恢复策略分散在 `AudioService`。
- 录音收尾失败时需要保留可恢复 `.tmp`，不能直接删除用户数据。
- 音频会话和电源策略互相依赖，临界电量或休眠前必须先停止并收尾。
- 旧代码包含固定板级引脚；换板时不得仅凭编译成功复用。

## 基于 main 的复用步骤

1. 先用纯内存测试建立 `AudioUse` 仲裁和抢占规则。
2. 使用 AudioProbe 单独验证 codec、I²S、喇叭和麦克风，不接 UI。
3. 引入固定 PCM 系统提示音，再引入闹钟循环音和可靠停止。
4. 接入 WAV 播放，验证拔卡和错误文件。
5. 最后接入录音临时文件、头部收尾和重启清理，并完成真机长录音测试。
