# 主题包与资源管理

## 目标

当前 main 已有 `UiTheme`、`UiTokens` 和内置资源；外部主题包服务只存在于本地历史对象。可复用的核心是“全部验证后再原子激活”，而不是旧清单格式本身。

## 推荐边界

- UI token 与资源解码分离；后台可验证文件，最终 LVGL 更新回到 UI 主循环。
- 清单、路径、文件数、尺寸和总字节数都有固定上限。
- 资源路径必须是受管相对路径，拒绝盘符、反斜杠、空组件和 `..`。
- 先验证全部资源，再写缓存和设置；任一步失败恢复旧缓存与旧主题。
- 默认主题始终可用，外部资源损坏不得阻止系统启动。
- 壁纸遵守 410×502 圆角安全区，正式资源先预览。

## 最小实现

1. 保留中性内置主题和集中 token。
2. 建立纯内存清单、路径和预算验证。
3. 接入只读 SD 预览，失败时不写设置。
4. 加入缓存、设置切换和故障回滚。
5. 完成色彩、裁切、内存峰值和连续切换真机验证后再开放导入。

## 主要风险

多次存储写入只能模拟事务，掉电仍可能产生半激活状态；支持过多图片格式会增加常驻解码成本；历史控件可能硬编码颜色而绕过 token。不能把特定角色美术名称当作系统接口。
