## 复用等级

**可直接参考。** 清单先验证、资源路径白名单、固定预算、缓存后原子切换、失败恢复旧设置，是后续所有可安装资源包应遵循的模式。

## 模块定位

主题包服务把外部 SD 资源转换为受验证的 `ThemeManifest` 和五色 palette。它不直接操作 LVGL；UI 主循环在成功激活后读取 token 并重绘现有控件。

## 职责与边界

- 解析最多 2,048 字节的 JSON 清单。
- 验证 schema、ID、palette、相对资源路径、扩展名、尺寸和文件大小。
- 壁纸固定 410×502 RGB565；一瞥图和图标包各不超过 512 KiB。
- 图标文件最多 64 个。
- 保存新缓存后再更新设置；设置写入失败时恢复旧缓存和旧设置。
- `ThemesApp` 只展示预览和确认，不绕过 `ThemePackageService`。

## 数据流与线程边界

```text
SD 主题目录
   │ parse + validate all resources
   ▼
ThemeManifest + ThemeValidationIssue
   │ saveThemeCache → saveSettings
   ▼
UI 主循环读取 token 并重绘
```

背景验证可以读取文件，但最终更改 LVGL 样式必须回到 UI 主循环。主题失败不能留下“新缓存 + 旧设置”或相反的半激活状态。

## 关键接口

| 项目 | 上限 |
|---|---:|
| manifest | 2,048 B |
| RGB565 壁纸 | `410 × 502 × 2` B |
| 一瞥资源 | 512 KiB |
| 图标包 | 512 KiB、64 文件 |
| 主题 ID | 24 字节 |
| 名称/作者 | 各 48 字节 |

## 验证边界

自动测试覆盖清单、路径、尺寸、默认主题、缓存和原子激活契约；不能证明真机色彩、圆角裁切、SD 导入、内存峰值或 50 次主题切换无泄漏。相关真机项目仍为 `PENDING`。

## 已知问题

- 原子性由多次存储写入和手工回滚模拟，不是真正跨介质事务；掉电窗口仍需真机故障注入。
- 资源格式支持范围是产品约束，不应为了兼容任意图片而把复杂解码器常驻固件。
- 主题导入成功不代表 UI 上所有遗留控件都使用 token；需检查硬编码颜色。
- 系统默认主题必须保持中性，不能把旧“流萤”美术别名当作系统契约。

## 基于 main 的复用步骤

1. 先保留 `UiTokens` 和中性默认主题，不启用外部包。
2. 建立纯内存 manifest 解析和路径/预算测试。
3. 接入只读 SD 验证与预览，失败时不写设置。
4. 加入缓存、设置切换和故障回滚测试。
5. 真机完成色彩、裁切、内存和连续切换验收后，再允许用户导入主题。
