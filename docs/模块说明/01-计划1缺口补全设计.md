# 计划 1 缺口补全设计

## 目标

在不改变现有 UI 布局和交互的前提下，补齐计划 1 审查发现的软件缺口，并为 Gate A 真机验收提供可重复采集的证据。完成的软件结果最终快进合并到 `main`。

## 方案

### OTA 准入

- `ResourceGovernor` 新增只读的 `canAcquire()`，使准入检查不必先占用资源。
- 省电/低电量约束同时拒绝 `Ota` 与 `HighRateMotion`。
- `SystemLifecycle` 对 `Updating` 采用带 `ResourceGovernor` 的显式重载；未提供治理器时拒绝进入更新态。
- 进入更新态前必须处于 `Active`，且 OTA 无播放、录音、传输、SD 写入或低电量冲突。

### 共享 I2C 边界

- 保留 `I2cBusManager` 作为唯一锁所有者。
- `LegacyBoardAdapter` 继续包装 RTC、PMU 和显示亮度，并补齐当前页面需要的系统电压字段。
- 当前运行时 RTC/PMU 读写迁移到 `LegacyBoardAdapter`；启动阶段 PMU/RTC 初始化也显式持有同一把锁。
- 新增轻量 `LockedRegisterDevice`，所有寄存器读写在一次带超时的锁事务中完成；QMI8658 与 ES8311 控制适配器仅固定设备类型和地址，不提前实现计划 3/4 的运动、播放或录音功能。
- 锁超时和总线错误按 `false` 返回；持锁期间不调用 LVGL。

### Gate A 证据

- 固件继续输出启动内存基线，并增加 EventBus 投递失败计数与锁屏进入桌面的最大耗时日志。
- Python 合约测试检查核心目录不依赖 LVGL、后台任务不调用 LVGL、旧事件位标志已删除、RTC/PMU UI 路径不再直接读取硬件。
- 自动探测串口设备；只有获得真实开发板日志和人工页面操作结果后才关闭 Gate A，不用估算替代真机数据。

## 非目标

- 不接入完整 IMU 功能、计步或抬腕。
- 不接入 ES8311 播放、录音和 I2S 数据链。
- 不修改 UI 视觉、布局、颜色或图片资源。

## 验收

- OTA 在资源冲突或低电量约束下被拒绝。
- 主工程不存在绕过适配器的运行时 RTC/PMU 读取。
- QMI8658、ES8311 控制寄存器只能通过带锁适配器访问。
- `verify_all.ps1` 全部通过。
- 无串口设备时 Gate A 保持“待真机”，并明确记录原因。
