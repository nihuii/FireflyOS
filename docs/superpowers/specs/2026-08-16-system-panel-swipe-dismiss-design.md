# FireflyOS 系统面板上滑返回修复设计

> 日期：2026-08-16
> 诊断基线：`main@6fceba2`
> 适用图形栈：Arduino + LVGL 8.3.11

## 1. 问题与目标

桌面顶部状态栏可以通过下拉打开系统面板，但面板展开后，大部分区域不能通过上滑返回桌面。需要让上滑手势可以从背景、卡片、按钮、滑杆和通知项起手，同时保留按钮轻点和滑杆横向调整。

本次目标是统一系统面板的手势事件所有权，并保证被识别为关闭手势的触摸不会继续触发原控件操作。

## 2. 已确认根因

`Firefly/Firefly.ino` 在父对象 `notif_panel`、顶部状态栏和窄把手上注册 `status_drag_cb`。控制中心与通知中心分别在 `notif_panel` 内创建 100%×100% 的子页面，按钮、卡片、标签和滑杆又构成更深的子对象树。

LVGL 8.3.11 的基础对象默认带有 `LV_OBJ_FLAG_CLICKABLE`。输入事件首先发送给最深的命中对象；只有当前对象显式具有 `LV_OBJ_FLAG_EVENT_BUBBLE` 时，普通事件才继续传给父对象。当前面板子树没有建立完整冒泡链，因此父面板无法获得从子对象起手的完整 `PRESSED → PRESSING → RELEASED/PRESS_LOST` 序列。

现有 `status_drag_cb` 的坐标限制、`-250` 位置门槛和 180ms 动画可以完成开合。故障位于事件进入状态机之前，不是动画或面板坐标计算错误。运行时代码最后由 `8e79cc2` 修改；之后的知识库提交没有改变该事件路径。

## 3. 交互语义

- 轻点按钮：执行原按钮操作，不移动或关闭面板。
- 横向拖动滑杆：调整原滑杆，不关闭面板。
- 从背景、卡片、按钮、滑杆或通知项起手，明显向上且纵向位移占优：关闭面板。
- 向下或横向占优的移动：不触发面板关闭。
- 被面板关闭手势接管后，原按钮不得在松手时产生 `CLICKED`，滑杆最终值必须恢复到手势开始前。
- 控制中心与通知中心切换后使用同一套规则。
- 面板关闭继续使用 180ms ease-out 动画；本次不改变布局、颜色、尺寸或触摸目标。

## 4. 方案选择

采用“完整事件冒泡链 + 纯方向仲裁器 + 父面板单一关闭所有者”。

不采用只依赖 `LV_EVENT_GESTURE` 的方案，因为它难以在自动测试中覆盖方向门槛，也无法可靠保存和恢复滑杆初值。不采用全屏透明捕获层，因为它会阻挡现有控件，需要额外实现命中转发或合成点击。

## 5. 组件与文件边界

### 5.1 PanelGestureArbiter

在 `libraries/FireflyOS/src/firefly/ui/` 增加不依赖 LVGL 的轻量方向仲裁器。它只保存按压起点和一次手势的决策状态，并输出：

- `Pending`：位移未达到门槛；
- `Ignore`：横向、向下或其他非关闭手势已经占优；
- `Dismiss`：向上且纵向位移占优。

初始门槛固定为 16px。只有 `dy <= -16` 且 `abs(dy) > abs(dx)` 时输出 `Dismiss`；达到 16px 后的其他方向输出 `Ignore`。一次按压作出 `Ignore` 或 `Dismiss` 后不再改变决定，释放或取消后复位。

### 5.2 面板事件接线

在 `Firefly/Firefly.ino` 完成控制中心、通知中心、把手和所有子控件创建后，递归遍历 `notif_panel` 的后代，为每个后代添加 `LV_OBJ_FLAG_EVENT_BUBBLE`。`notif_panel` 自身不添加该标志，使事件在面板处停止。

父面板只订阅 `LV_EVENT_PRESSED`、`LV_EVENT_PRESSING`、`LV_EVENT_RELEASED` 和 `LV_EVENT_PRESS_LOST`。将现有同时负责开、关的 `status_drag_cb` 拆成两个职责明确的入口：顶部状态栏回调只负责下拉打开，父面板回调只负责上滑关闭。不再依赖窄把手作为关闭事件入口，也不使用 `LV_EVENT_ALL` 扩大无关事件范围。

当前面板子对象都在初始化阶段创建，通知刷新只显示、隐藏和更新既有卡片，因此初始化结束后的单次递归配置足够覆盖当前对象树。后续若引入运行时动态子对象，创建路径必须同步添加事件冒泡标志或再次执行配置函数。

### 5.3 面板手势状态

在 `FireflyInteraction.cpp` 保存仅供 UI 主循环使用的面板手势状态：原始命中对象、按压起点、手势决定、音量快照和亮度快照。

事件流程如下：

1. `PRESSED`：仅在面板完全展开且没有关闭动画时开始跟踪，记录坐标、原始命中对象及两个滑杆值。
2. `PRESSING`：把当前坐标交给 `PanelGestureArbiter`。
3. `Pending`：不处理，控件保留正常点击候选状态。
4. `Ignore`：停止面板手势跟踪，后续事件继续由原控件处理。
5. `Dismiss`：先将面板手势标记为已接管，调用 `lv_indev_wait_release()`，使最终释放成为 `PRESS_LOST` 而不是 `CLICKED`；随后恢复快照中的滑杆状态，停止现有面板动画并启动到 `-LCD_HEIGHT` 的 180ms ease-out 动画。
6. `RELEASED` 或 `PRESS_LOST`：无条件清理手势状态，避免下一次触摸继承旧状态。

`lv_event_get_target(e)` 用于记录最初命中的子对象，`lv_event_get_current_target(e)` 应保持为 `notif_panel`。所有 LVGL 查询、标志修改、滑杆恢复和动画调用均发生在 UI 主循环事件回调中。

## 6. 滑杆与按钮保护

按钮只在未被关闭手势接管的正常释放路径产生点击。`Dismiss` 时调用 `lv_indev_wait_release()`，LVGL 在物理释放时发送 `PRESS_LOST` 并跳过 `RELEASED/SHORT_CLICKED/CLICKED`。

滑杆可能在方向门槛形成前先产生一次 `VALUE_CHANGED`，因此 `PRESSED` 时必须保存 `volume_level` 和 `screen_brightness`。若手势成为 `Dismiss`：

- 先恢复 `volume_level`，调用 `save_volume_preference()` 覆盖门槛形成前可能写入的 Preferences 值，再调用 `refresh_sound_alarm_ui()` 同步控制中心和设置页；
- 调用 `set_screen_brightness_level(brightness_snapshot)` 恢复 `screen_brightness`、背光硬件和运行时状态 UI；
- 仅当快照值与当前值不同时执行对应恢复，避免无意义的 Preferences 写入、硬件写入和刷新。

恢复期间先保持“手势已接管”状态，使程序触发的滑杆同步即使产生 `VALUE_CHANGED` 也不能重新进入关闭仲裁。不得只改滑杆外观。横向手势成为 `Ignore` 后不恢复快照，保留正常调节结果。

## 7. 动画和异常收尾

- 开始关闭前删除 `notif_panel` 上尚未结束的同类动画，避免两个动画同时写 y 坐标。
- 关闭目标统一使用 `-LCD_HEIGHT`，不再混用字面量 `-502`。
- 释放、`PRESS_LOST`、路由切换、锁屏和息屏路径都必须清理手势跟踪状态。
- 面板未完全展开时忽略子控件关闭手势，避免打开动画与关闭仲裁竞争。
- 输入设备为空或面板对象不存在时只清理状态并返回，不访问无效对象。

## 8. 测试设计

### 8.1 自动测试

在 `tests/FireflyCoreTests/FireflyCoreTests.ino` 为纯仲裁器增加以下用例：

- 位移不足 16px 保持 `Pending`；
- 明显向上且纵向占优返回 `Dismiss`；
- 同样距离下横向占优返回 `Ignore`；
- 向下返回 `Ignore`；
- 决策后继续移动不改变结果；
- `reset()` 后可开始新手势。

在 `tests/python/test_repository_contracts.py` 增加源码接线契约，要求：

- 面板后代递归添加 `LV_OBJ_FLAG_EVENT_BUBBLE`；
- 父面板订阅四个明确事件，而不是只依赖窄把手；
- 关闭接管路径调用 `lv_indev_wait_release()`；
- 关闭目标使用 `-LCD_HEIGHT`；
- 后台文件仍不包含 LVGL 调用。

随后运行目标 Python 测试、核心测试固件构建、知识库校验和主固件构建。完整 Python 套件中已知的基线文档缺失必须继续单独报告，不得归因于本修复。

### 8.2 真机验收

在控制中心和通知中心分别执行：

- 从背景、卡片、按钮、滑杆拇指和通知项起手上滑，每类 20 次；
- 轻点每类按钮 20 次，功能只执行一次且面板不误关闭；
- 两个滑杆各横向调节 20 次，数值连续且面板不误关闭；
- 从滑杆起手纵向上滑 20 次，面板关闭且最终数值与手势开始前一致；
- 控制中心与通知中心来回切换 20 次，每次都能关闭；
- 人为中断触摸或滑出对象，下一次触摸仍能正常开始；
- 连续操作期间无重启、卡死、重复点击或超过 250ms 的无反馈阻塞。

自动测试和构建通过不等于上述真机项目通过。

## 9. 非目标与后续边界

本修复不调整视觉资源，不新增页面，不修改 BOOT/一瞥/息屏策略，不处理 TouchLib 共享 I2C、电源轮询或其他硬件服务。完成并取得真机证据后，才进入共享 I2C/电源阶段。

## 10. 回退策略

若事件冒泡导致未预期的控件副作用，回退本次面板手势提交即可恢复原接线。回退不得恢复已删除的历史工作树文档或 TouchLib 压缩包，也不得改变知识库对当前能力的分类。
