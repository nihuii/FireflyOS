# FireflyOS 轻量知识库重写设计

> 日期：2026-08-16
> 当前基线：`main@fab5509`
> 用途：为后续代码设计提供低 token 消耗的思路参考

## 背景

远端现仅保留 `main`。旧 `codex/*` 远端分支和 `.worktrees/*` 路径已经失效，但本地 Git 对象中仍保留计划 3～6 的历史实现快照 `e4fb0d1ff71bcc0330b507fa90c653be9929e611`。现有知识库仍把旧分支描述为远端来源，并包含大量实现片段、测试数字和建设过程，不适合当前基于主分支的小步开发。

## 重写目标

1. 以当前 `main@fab5509` 为唯一开发基线。
2. 将知识库定位为设计思路卡片，不作为可整批恢复的源码镜像。
3. 保留旧模块的边界、状态机、失败经验和安全约束。
4. 所有日常查阅路径使用仓库相对路径，不依赖工作树或已删除远端分支。
5. 将 Markdown 总量压缩约 40%～60%，单个模块可独立阅读。

## 文件结构

- `README.md`：当前基线、使用方式、模块索引、全局约束。
- `00-源码清单与取回方法.md`：当前源码入口和可选的本地历史对象读取方式。
- `01`～`13`：统一模块卡片，包含目标、推荐边界、最小实现、主要风险和参考路径。
- `14-主程序集成与后续复用顺序.md`：基于当前主分支的渐进开发顺序。
- `知识库设计.md`、`知识库实施计划.md`：压缩成简短维护说明，不再记录冗长建设过程。
- `validate_knowledge.py`：检查文件、链接、禁用路径和本地历史对象可读性。

## 内容边界

保留：

- LVGL 仅由 UI 主循环访问。
- 410×502 圆角安全区和至少 48px 触摸区。
- 固定容量队列、快照、单一硬件资源所有者和独立运行优先。
- UI 覆盖层、共享 I²C、BOOT/息屏、烧录链路、无线、OTA 和恢复出厂的关键失败经验。
- 自动验证与真机验收的证据边界。

移除或压缩：

- 已删除远端分支的“已推送”声明。
- `.worktrees/*` 和绝对工作树路径。
- 大段旧源码、完整测试列表、APK/bin 哈希和过期构建数字。
- 重复的计划进度、Git 历史和知识库生成过程。

## 来源与取回规则

- 默认只读取当前仓库中的 `Firefly/`、`libraries/FireflyOS/`、`docs/`、`tests/` 和 `tools/`。
- `e4fb0d1` 仅作为本机可选历史锚点，不保证能从远端重新下载。
- 旧实现只能通过 `git show <commit>:<path>` 查看，不直接覆盖当前同名文件。
- 若本地历史对象消失，模块卡片仍应能够独立说明设计思路。

## 验证标准

- 知识库不包含 `.worktrees/`、`origin/codex/` 或旧远端可恢复声明。
- README 和每张模块卡片均能独立说明用途与风险。
- 内部 Markdown 链接有效。
- 当前基线写为 `main@fab5509`。
- 旧提交存在时校验其对象；不存在时给出明确提示，不把远端恢复当作保证。
- 不修改知识库之外的现有用户变更，不提交、不合并、不推送。
