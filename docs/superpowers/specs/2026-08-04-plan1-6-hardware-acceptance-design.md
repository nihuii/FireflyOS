# FireflyOS 计划 1～6 真机功能验收表设计

## 1. 目标

在项目根目录建立一份统一的计划 1～6 真机功能验收表，明确六个 worktree 分别需要烧录、操作、测量和留存的证据；同时更新 `docs/项目介绍-对话衔接版.md`，使后续对话能够从六分支链和最新待验状态继续工作。

## 2. 判定口径

- 自动测试、固件编译、Android JVM 单元测试和 Debug APK 只作为验收前置证据，不计为真机通过。
- 新表中的正式真机项目全部从 `PENDING` 开始。计划 2 曾“基本跑通”只记录为历史备注，不抵扣 Gate B 项目。
- 每项只允许 `PENDING`、`PASS`、`FAIL`、`BLOCKED` 四种状态，并要求填写日期、固件提交、设备、步骤、结果、证据路径和问题编号。
- 后序 worktree 包含前序能力，但每轮只验收该分支新增职责及必要的前序回归，避免同一功能在六个分支中重复签字。
- 真机发现问题时修在最早责任分支；修复复测通过后，按前序到后序使用 merge 同步。

## 3. 文档结构

正式验收表采用一个文件、两级结构：

1. 总矩阵：worktree、分支、阶段 Gate、主要验收范围、前置 Gate、下游目标。
2. 六个工作树分表：每行包含 ID、功能/场景、操作与次数、通过标准、必留证据、状态。

各阶段范围如下：

- 计划 1 / `firefly-core`：基线页面、HAL、EventBus、BOOT、息屏/唤醒、内存和转场基线，关闭 Gate A。
- 计划 2 / `ui-shell`：六张批准预览、圆角安全区、48px 触摸区、导航/覆盖层、50 次页面回收和转场，关闭 Gate B。
- 计划 3 / `core-apps-power-imu`：RTC、闹钟、计时、设置、BOOT/PWR、QMI8658、计步、抬腕、LightSleep 唤醒矩阵和阶段功耗。
- 计划 4 / `storage-audio-media`：SD、AudioProbe、铃声抢占、Files/Music/Recorder/Themes、拔卡恢复、长稳、触摸和空闲功耗，完成独立设备媒体能力。
- 计划 5 / `ble-android`：沿用 D-01～D-12，覆盖 BLE 互操作、安全、权限、解绑、冲突同步、断连独立运行、天气/媒体/找设备、压力和实屏。
- 计划 6 / `wifi-weather-ota`：Wi-Fi 配网与功耗、NTP、天气缓存、1MB/32MB 传输、SD/HTTPS OTA、断电与回滚、24 小时、400mAh、故障降级、恢复出厂、隐私和 Gate E。

## 4. 执行与同步关系

固定顺序为：

```text
codex/firefly-core
  -> codex/ui-shell
    -> codex/core-apps-power-imu
      -> codex/storage-audio-media
        -> codex/ble-android
          -> codex/wifi-weather-ota
```

每个 worktree 开始前记录分支、HEAD、自动验证结果和烧录产物哈希。全部本阶段项目通过后，先将责任分支合并到本地 `main`，再按用户授权决定是否推送；随后把修复逐级 merge 到下游。任何未通过项不得被下游自动结果覆盖。

## 5. 对话衔接版更新

衔接版应：

- 把当前开发现场扩展为第六 worktree `wifi-weather-ota`，并明确其改动尚未提交。
- 记录计划 6 软件收口和最新自动证据，但继续把 Gate D、Gate E 与所有前序真机 Gate 标为 `PENDING`。
- 增加新验收表的绝对路径和六分支真机执行顺序。
- 更新“建议下一步”和新对话启动提示，移除“不要开始计划 6”的过时说明。
- 保留不删除用户文件、不覆盖 `image\图片生成提示词`、不擅自提交/合并/推送以及 LVGL 单线程边界。

## 6. 完成标准

- 新验收表能直接告诉操作者六个 worktree 分别验收什么、做多少次、什么算通过、证据放哪里。
- 计划 5 的 D-01～D-12 和计划 6 的 E-01～E-12 不被缩写成模糊摘要。
- 衔接版中的 Git、软件状态、自动验证和真机状态互不混淆。
- 文档不出现未定义占位符，不声称任何尚未执行的真机项目已经通过。
