## 1. 项目定位

`FireflyOS` 是面向微雪 `ESP32-S3-Touch-AMOLED-2.06` 的轻量手表系统，使用 Arduino 与 LVGL 8.3.11 开发。系统视觉参考《崩坏：星穹铁道》角色“流萤”，正式角色图、图标和主题美术目前仍以占位资源为主。

项目坚持独立运行优先：没有手机时，时间、闹钟、电源、活动、本地媒体、录音和本地缓存等核心能力仍应工作；Android、BLE、Wi-Fi、天气、日程、通知和 OTA 是增强项，不能反向破坏手表本地功能。设计优先级是稳定、低资源、固定容量、模块化和可持续扩展。

## 3. 不可破坏的约束

- LVGL 只能由 Arduino UI 主循环访问；后台任务、BLE 回调和 GATT 解析只能采样、计算、写入固定容量队列或投递事件。
- 新增共享 I2C 访问必须经过带超时的互斥边界。
- UI 必须适配 410 × 502 圆角屏；主要触摸目标至少 48 × 48px，Android 端关键按钮至少 48dp。
- 正式 UI 先提供预览；用户若授权不中断执行，仍需保留预览和最终视觉复核记录。
- 正式图标、封面和角色美术先使用占位资源。
- 列表、队列、导航、缓存、媒体索引、BLE 分片和 GATT 操作使用固定容量。
- 自动测试、桌面编译、Android 单元测试、APK 构建和真机验收是不同证据；未执行的真机项目不得写成通过。
- `image\图片生成提示词` 是用户未跟踪资源，禁止删除或覆盖。
- 未经用户明确授权，不要提交、合并、推送、删除文件或开始计划 7。

## 8. 计划 5：BLE 与 Android 伴侣应用

计划文件：`.worktrees\ble-android\docs\执行计划\05-BLE与Android伴侣应用.md`

截至 2026-07-30，计划 5 Task 1～9 已形成软件实现，并已提交为 `15d675d feat: implement BLE and Android companion`，远端分支为 `origin/codex/ble-android`。Task 10 Step 1 自动验证通过，Gate D 真机矩阵仍为 `PENDING`。自动验证和 Debug APK 构建不能写成真机通过。

已形成的软件能力：

- BLE 协议 v1：固定 GATT UUID、11 字节帧头、CRC16、序号、ACK、动态 MTU 分片、消息类型、Error 错误码与黄金帧。
- 固件侧 `FrameCodec` 与 `ConnectivityService`：逻辑 payload 1024 字节上限，ATT 块最大 180 字节，MTU 23 回退时最多 147 片，单帧 ACK 重试缓存，串行接收、ACK 超时与有限重试。
- 安全链路：Secure Connections、配对确认、128-bit app token、敏感消息 HMAC-SHA256 截断 8 字节、重放拒绝、Unauthorized 响应、连续失败断开。
- 配对/解绑事务：配对记录区分 provisional/confirmed，启动时回滚未确认记录；Android 待解绑 token 跨进程持久化，ACK 写入失败或断线时保留恢复能力，双方 ACK 后提交清理。
- Android 伴侣应用：Views/XML 工程，BLE/通知/日历最小权限，15 秒扫描，GATT 串行操作，MTU 185 请求与回退，通知转发、设置同步、主题、天气、日程、媒体控制、找手机、找手表和解绑入口。
- Android 预览与配对预览已有用户批准记录。
- 提交前修复过的关键审查点包括：TX 特征改为 notify-only，严格 ACK 帧判定，解绑时先清 BLE bonds 再清 token，Android 使用 Hello/ACK 门禁避免过早业务重放，GATT 操作加入 2 秒超时。
