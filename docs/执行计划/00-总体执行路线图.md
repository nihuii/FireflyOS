# FireflyOS 总体执行路线图 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有 FireflyOS 原型渐进迁移为可独立运行、可与 Android 手机增强互联、覆盖板载硬件能力的模块化手表系统。

**Architecture:** 保留 Arduino + LVGL 8.3.11 技术栈，将新增代码收敛到本地 `FireflyOS` Arduino 库中，主草图只负责启动和循环。所有 LVGL 调用固定在 UI 核，后台服务通过有界事件队列与状态快照驱动 UI；应用静态注册、页面按需创建。

**Tech Stack:** ESP32-S3、Arduino-ESP32、LVGL 8.3.11、Arduino_GFX、TouchLib、SensorLib、XPowersLib、ES8311/I2S、SD、BLE、Wi-Fi、Android/Kotlin。

## 4. 构建与测试基线

当前已使用 Arduino IDE 内置的 Arduino CLI 1.4.1 建立可复现构建入口，ESP32 Arduino Core 版本为 2.0.17。构建脚本会自动定位本机 Arduino IDE 内置 CLI，也支持通过环境变量覆盖路径。

统一验证命令：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\verify_all.ps1
```

期望顺序：

```text
[1/4] Python contract tests: PASS
[2/4] Firmware core tests compile: PASS
[3/4] Firefly firmware compile: PASS
[4/4] Documentation checks: PASS
```

真机验证不能被编译测试替代。每个阶段至少记录：

- 固件大小。
- 启动后内部 SRAM 与 PSRAM 可用量。
- 关键页面触摸响应。
- 是否出现看门狗复位或跨核 LVGL 调用。
- 400mAh 电池下的代表性功耗数据。

## 5. 统一开发循环

每个功能任务使用以下顺序：

- [ ] **Step 1: 写失败测试或可复现检查**

  测试应验证一个明确行为，例如“关键事件在队列满时仍可入队”。

- [ ] **Step 2: 运行检查并确认失败原因正确**

  ```powershell
  python -m unittest discover -s tests\python -v
  ```

  Expected: 新测试失败，且失败信息指向尚未实现的行为。

- [ ] **Step 3: 写满足测试的最小实现**

  只实现当前测试覆盖的行为，不顺带加入下一阶段功能。

- [ ] **Step 4: 运行模块测试与完整验证**

  ```powershell
  powershell -ExecutionPolicy Bypass -File .\tools\verify_all.ps1
  ```

  Expected: 全部检查通过。

- [ ] **Step 5: 真机验证并记录证据**

  将串口日志、截图、功耗或操作结果写入对应模块说明。

- [ ] **Step 6: 提交单一职责变更**

  ```powershell
  git add <本任务文件>
  git commit -m "<type>: <单一变更说明>"
  ```

## 6. 阶段门槛

### Gate A：基础架构可用

- 主界面行为与当前版本一致。
- EventBus、StateStore 和 CapabilityRegistry 通过测试。
- 新核心代码不依赖 LVGL。
- `Firefly.ino` 开始缩小，但旧功能没有被一次性迁走。

### Gate B：UI Shell 可用

- 410 × 502 全局页面预览获得用户批准。
- 锁屏、桌面、状态栏、控制中心和通知中心使用统一 Shell。
- 普通应用页面可以打开、返回和释放。
- 圆角安全区和触摸热区通过真机检查。

### Gate C：独立设备能力完整

- 时间、闹钟、计时、电源、活动、SD、音乐和录音无需手机即可工作。
- PWR/BOOT 行为一致。
- 屏幕关闭后进入真实低功耗状态并可靠唤醒。
- 400mAh 代表性日常使用达到 24 小时目标，或明确记录未达标数据与下一轮优化项。

### Gate D：手机增强可用

- 手机断连不影响 Gate C 功能。
- BLE 配对、通知、设置和天气摘要同步可恢复。
- Android 应用可解除绑定并清除手表端关联状态。

### Gate E：联网与发布可用

- Wi-Fi 只在明确会话中开启并超时关闭。
- OTA 可校验、安装、确认和回滚。
- 24 小时稳定性、SD 拔插、BLE 重连、Wi-Fi 失败和低电量测试通过。
- 中性基础主题与流萤主题资源边界清晰。

## 8. 明确不纳入本轮路线的内容

- 动态加载二进制应用。
- 多用户账户与强制云服务。
- 语音助手。
- GPS 导航、指南针、心率、血氧和医疗结论。
- 未经实测的睡眠监测或跌倒检测稳定功能。
- 大面积实时模糊、持续粒子和高帧率全屏 GIF。
