# 计划 1A：计划 1 缺口补全

## 1. 目标与当前状态

本计划只收口计划 1 已实现核心的证据缺口。EventBus 拒绝计数、受锁寄存器设备、RTC/PMU 板级适配和 Gate A 日志入口已有不同程度实现；它们需要重新核对当前调用链和真机证据。OTA 联合准入不属于本计划。

## 2. 知识库依据

- [01-核心运行时与事件状态](../../knowledge/01-核心运行时与事件状态.md)
- [13-诊断、恢复出厂与发布闭锁](../../knowledge/13-诊断恢复出厂与发布闭锁.md)

## 3. 前置条件与禁止事项

- 先完成计划 1 的当前源码与自动证据盘点。
- 不迁移 Touch、不开启后台硬件轮询；共享 I²C 归计划 3。
- 不加入更新状态、低电 OTA 规则、签名或首启确认。
- 不依据旧分支、旧 Gate 表或旧串口记录宣布完成。

## 4. 功能范围与明确非目标

范围是核心拒绝诊断、受锁寄存器边界、RTC/PMU 值对象调用和 Gate A 证据。非目标是 UI 手势、电源策略、IMU 业务、存储、无线与更新。

## 5. 分任务实施顺序

### Task 1：核心拒绝与资源诊断收口

- [ ] **文件范围：** `EventBus.*`、`ResourceGovernor.*`、`FireflyCoreTests.ino`。
- [ ] **预期失败：** 先增加队列满、冲突拒绝和计数保持测试；缺失行为必须产生明确失败。
- [ ] **最小实现：** 只补固定计数和枚举原因，不增加无界日志。
- [ ] **验证命令：** 编译并运行核心测试固件。
- [ ] **预期结果：** 拒绝路径可观察且不改变事件优先级。

### Task 2：受锁设备与板级值对象边界收口

- [ ] **文件范围：** `libraries/FireflyOS/src/firefly/hal/`、`Firefly/Firefly.ino`、`Firefly/FireflyInteraction.cpp` 和相关契约测试。
- [ ] **预期失败：** 测试先捕获非法缓冲区、未持锁寄存器访问或 UI 文件直接进行 RTC/PMU 状态读取。
- [ ] **最小实现：** 保持单次锁事务和快照返回；不把 Touch 接入或引入后台并发。
- [ ] **验证命令：** 运行核心测试、Python 契约和主固件构建。
- [ ] **预期结果：** 当前 RTC/PMU 路径可追踪且 LVGL 不进入 HAL。

### Task 3：Gate A 证据收口

- [ ] **文件范围：** 当前串口诊断入口和 Gate A 记录。
- [ ] **预期失败：** 无目标板、无启动日志或无法区分上传链路时，验收保持待真机。
- [ ] **最小实现：** 记录一次启动摘要、拒绝数、内存水位和能力失败原因。
- [ ] **验证命令：** 运行完整自动验证并在可用设备上采集串口日志。
- [ ] **预期结果：** 自动结果与真机结果分栏；缺设备时明确阻塞而非继承旧结论。

## 6. 自动验证

运行 `python knowledge/validate_knowledge.py`、`python -m unittest discover -s tests/python -v` 和 `powershell -ExecutionPolicy Bypass -File tools/verify_all.ps1`。预期全部软件检查通过，未执行硬件项继续标记待真机。

## 7. 真机验收

- [ ] 采集冷启动、正常运行和一个受控能力失败的日志。
- [ ] 验证诊断输出有界且不会造成明显 UI 阻塞。
- [ ] 核对 RTC/PMU 读取失败时的降级界面，不显示虚假数据。

## 8. 退出门槛与下一计划

计划 1/1A 的软件缺口和 Gate A 证据均关闭后，进入计划 2A。若设备证据缺失则保持待真机；不通过分支操作或更新功能绕过此门槛。
