# 计划 1：工程基线与模块化核心

## 1. 目标与当前状态

目标是在 `main@fab5509` 上冻结可复现构建和现有核心边界，补齐诊断与 Gate A 真机证据，而不是重新创建已经存在的 EventBus、StateStore、SystemLifecycle、AppRegistry、AppManager、ResourceGovernor、CapabilityRegistry、HAL 和构建工具。

上述核心原语属于“当前已有”；队列压力、栈/堆水位、硬件探测失败原因和长时间恢复仍为“待真机”。有界诊断服务仅部分存在，恢复出厂和发布闭锁仍待后续开发。当前 Python 契约还要求一份并不存在于 HEAD 的 `docs/模块说明/00-当前基线.md`；这是计划 1 待补的当前测量文档，不是本轮对齐任务可恢复的历史文件。

- [01-核心运行时与事件状态](../../knowledge/01-核心运行时与事件状态.md)
- [13-诊断、恢复出厂与发布闭锁](../../knowledge/13-诊断恢复出厂与发布闭锁.md)
- [当前源码清单](../../knowledge/00-源码清单与取回方法.md)

卡片 01 和 13 的唯一主要计划是计划 1；计划 6 只负责把恢复出厂和 Release 闭锁接入完整系统。

## 3. 前置条件与禁止事项

- 从当前根 worktree 和完整脏状态开始，不恢复用户删除或知识库改写。
- 只在 UI 主循环消费 UI 事件；核心与 HAL 不依赖 LVGL。
- 不把 OTA 准入或签名更新加入 Gate A；只保留通用资源治理能力。
- 不扩大事件负载、队列和诊断缓存来掩盖丢弃问题。
- 本计划不执行任何 Git 交付动作。

## 4. 功能范围与明确非目标

范围包括构建配置冻结、核心契约、事件丢弃与资源水位、能力探测结果、串口 Gate A 记录和故障降级。非目标包括重新设计 UI、共享 Touch/I²C、完整电源/IMU 服务、存储媒体、无线、OTA、恢复出厂和发布候选。

## 5. 分任务实施顺序

### Task 1：冻结当前构建与核心契约

- [ ] **文件范围：** `Firefly/build_opt.h`、`Firefly/partitions.csv`、`libraries/FireflyOS/src/firefly/core/`、`tests/python/`、`tests/FireflyCoreTests/`，以及计划创建的 `docs/模块说明/00-当前基线.md`；除发现事实错误外不改实现。
- [ ] **预期失败：** 当前 `test_baseline_document_has_required_metrics` 因基线文档不存在而失败；其他新契约应能在核心容量、分区偏移、LVGL 版本或 core 设置被意外改变时失败。
- [ ] **最小实现：** 用当前构建和真机测量创建基线文档，固定当前 32MB app0/app1、otadata、FFat、coredump 布局和核心容量边界，不复制旧固件尺寸或测试计数。
- [ ] **验证命令：** `python -m unittest discover -s tests/python -v`，随后运行 `powershell -ExecutionPolicy Bypass -File tools/verify_all.ps1`。
- [ ] **预期结果：** Python 契约通过，验证脚本使用当前 Sketchbook 与 LVGL 8.3.11；硬件项仍标记待真机。

### Task 2：补齐有界诊断和失败原因

- [ ] **文件范围：** `libraries/FireflyOS/src/firefly/core/EventBus.*`、`CapabilityRegistry.*`、`ResourceGovernor.*`、计划创建的最小诊断记录接口及核心测试。
- [ ] **预期失败：** 先证明队列拒绝、资源冲突或硬件探测失败没有可读取的有界原因，或现有测试不能区分它们。
- [ ] **最小实现：** 增加固定计数、枚举原因和固定 RAM 环形记录；热路径不打印、不写卡、不动态增长。
- [ ] **验证命令：** 编译并运行 `tests/FireflyCoreTests/FireflyCoreTests.ino`，再运行 Python 仓库契约。
- [ ] **预期结果：** 队列满明确拒绝并计数，能力快照区分未探测、可用和失败；正常时序不被诊断 I/O 改变。

### Task 3：建立 Gate A 当前真机记录

- [ ] **文件范围：** `Firefly/FireflyInteraction.cpp` 的现有诊断入口、串口记录和对应模块说明；不得顺带改 UI 或设备策略。
- [ ] **预期失败：** 缺少设备或串口证据时 Gate A 保持待真机，而不是从旧日志推断通过。
- [ ] **最小实现：** 一次性输出版本、分区、PSRAM/堆水位、事件拒绝数和能力探测摘要；避免循环刷屏。
- [ ] **验证命令：** 当前主固件完整构建；上传后采集一次冷启动和一次受控错误日志。
- [ ] **预期结果：** 日志能区分构建失败、上传链路失败、启动失败和能力降级；无设备时明确记录阻塞原因。

- `git diff --check -- docs/执行计划 knowledge`：无空白错误；自动结果不替代 Gate A 真机证据。
