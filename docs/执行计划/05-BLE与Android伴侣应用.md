# 计划 5：BLE 与 Android 伴侣应用

## 1. 目标与当前状态

当前 main 只有 BLE 能力枚举和 UI 占位，没有 BLE 帧、GATT 外设、配对服务或 Android 工程，状态为“待开发”。本计划从最小 Hello、Pair、Ack 和 Error 开始，建立安全、有界、可恢复的手表/Android 通道，再逐项加入通知和设置同步。

## 2. 知识库依据

- [08-BLE 协议、配对与通知](../../knowledge/08-BLE协议配对与通知.md)
- [09-Android 伴侣应用](../../knowledge/09-Android伴侣应用.md)

卡片 08 和 09 的唯一主要计划是计划 5。

## 3. 前置条件与禁止事项

- Gate C 的本地能力保持稳定；手机断连不能影响时间、闹钟、设置或本地媒体。
- BLE 回调只复制有界字节并投递事件，不解析业务、不调用 LVGL。
- 链路加密不替代应用认证；敏感消息必须验证 token/HMAC 和重放。
- 大文件不走 BLE；Wi-Fi/传输仅在计划 6 使用 BLE 协商。
- `AndroidCompanion/` 是计划创建路径，不得描述为当前目录；历史对象仅作人工参考。

## 4. 功能范围与明确非目标

范围包括版本化帧、严格 ACK、Secure Connections 配对、敏感消息认证、手表 GATT、Android 最小工程/GATT 队列、通知摘要和设置同步。非目标包括 iOS、云账户、BLE 大文件、静默权限获取、生产密钥入库和网络/OTA 业务。

## 5. 分任务实施顺序

### Task 1：冻结最小协议与双端黄金帧

- [ ] **文件范围：** 计划创建的手表协议目录、协议说明、Python/C++/Kotlin 测试向量。
- [ ] **预期失败：** 小端、长度、CRC、MTU 分片、未知类型、严格 ACK 和超长负载测试先失败。
- [ ] **最小实现：** 只定义 Hello、PairRequest、PairConfirm、Ack、Error；固定头、payload 和接收队列容量。
- [ ] **验证命令：** 运行 Python/C++ 黄金帧测试；Android 工程创建后运行 Kotlin 同向量测试。
- [ ] **预期结果：** 三端字节完全一致，ACK 必须匹配类型、标志、序号和空载荷。

### Task 2：实现手表 GATT 与会话状态机

- [ ] **文件范围：** 计划创建的 BLE HAL、ConnectivityService、EventBus 适配和测试。
- [ ] **预期失败：** 队列满、分片超时、断连、重复序号、认证前敏感消息和取消测试先失败。
- [ ] **最小实现：** 回调只入队；认证、重放、业务入队、sequence 推进、ACK 严格按顺序执行。
- [ ] **验证命令：** 运行协议/会话测试、主固件构建和 BLE 外设探针。
- [ ] **预期结果：** 连接不等于会话就绪，失败会清理临时配对和待确认发送。

### Task 3：完成安全配对与解绑

- [ ] **文件范围：** 手表配对覆盖层、会话服务、NVS 配对 owner 和安全测试。
- [ ] **预期失败：** 用户拒绝、超时、伪造确认、重放、进程中断和部分持久化测试先失败。
- [ ] **最小实现：** Secure Connections、MITM 与手表确认；双方确认后才稳定保存，解绑幂等清理。
- [ ] **验证命令：** 运行安全向量并在当前手表与至少两台 Android 手机上执行配对/取消/解绑。
- [ ] **预期结果：** 未认证客户端不能执行敏感命令，配对失败不留下半稳定凭据。

### Task 4：创建 Android 最小工程与串行 GATT 客户端

- [ ] **文件范围：** 计划创建 `AndroidCompanion/`，包含权限状态、BLE codec、GATT 队列、私有存储和单元测试。
- [ ] **预期失败：** 权限拒绝、操作超时、回调乱序、进程重启和原子存储测试先失败。
- [ ] **最小实现：** 单次限时扫描、串行 MTU/服务/CCCD/写操作；Activity 只渲染状态，回调切主 Looper。
- [ ] **验证命令：** 运行 Android JVM 单测和 Debug 构建，再做真实权限与系统回收测试。
- [ ] **预期结果：** Debug APK 只算自动证据；权限和多厂商互操作仍需真机记录。

### Task 5：逐项加入通知与设置同步

- [ ] **文件范围：** 手表通知/设置服务、Android 通知监听与同步组件、UI 快照和测试。
- [ ] **预期失败：** 长文本、重复、删除、隐私隐藏、revision 冲突、断线重放和队列满测试先失败。
- [ ] **最小实现：** 先有界通知摘要，再单项设置；安全 Hello 获得严格 ACK 后才重放。
- [ ] **验证命令：** 运行双端业务测试、Android 构建和实际通知/设置互操作矩阵。
- [ ] **预期结果：** 手表只保存必要字段，锁屏隐私设置生效，最近明确用户操作赢得冲突。

## 6. 自动验证

运行 `python knowledge/validate_knowledge.py`、协议黄金帧、手表核心测试、Android JVM 测试及两端构建。预期边界、认证、重放、严格 ACK、超时与重启恢复均有自动检查。

## 7. 真机验收

- [ ] 当前手表与至少两种 Android 品牌/版本完成扫描、配对、取消、重连和解绑。
- [ ] 验证真实 MTU、CCCD、系统配对弹窗、权限拒绝和进程回收。
- [ ] 连续连接 8 小时记录断线恢复、队列水位和功耗。
- [ ] 通知新增/删除、中文长文本、隐私隐藏和设置冲突均有真机记录。
- [ ] 手机关机或离开后，本地时间、闹钟、设置和媒体不受影响。

## 8. 退出门槛与下一计划

Hello/Pair/Ack、安全会话和 Android 最小互操作必须先稳定，再逐项开放通知/设置。Gate D 关闭后进入计划 6；网络凭据、传输和 OTA 不得提前塞入本计划。
