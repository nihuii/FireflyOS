# 计划 3：核心应用、电源与 IMU

## 1. 目标与当前状态

当前 main 已有 RTC 读写、电池/充电、主程序级双闹钟、BOOT/触摸交互、I²C 管理器和 `Qmi8658ControlAdapter`；这些是“部分已有、待真机”，不是独立 TimeService、AlarmService、PowerService 或 MotionService 闭环。Activity 仍是 UI 占位。

本计划先统一 Touch/I²C 所有权，再逐项收敛时间、闹钟、电源、按键、IMU 和活动能力。

## 2. 知识库依据

- [03-时间闹钟与调度](../../knowledge/03-时间闹钟与调度.md)
- [04-电源、按键、触摸与 IMU](../../knowledge/04-电源按键触摸与IMU.md)

卡片 03 和 04 的唯一主要计划是计划 3。

## 3. 前置条件与禁止事项

- 计划 2A 和 Gate B 的手势/硬件基线已稳定，否则停止。
- Touch、RTC、PMU、IMU 必须经过同一 I²C 所有权；完成前禁止后台并发轮询。
- 后台只投递固定事件或快照，不访问 LVGL、页面对象或显示句柄。
- 浅睡默认关闭，只有唤醒矩阵全部真机验证后才开放。
- 不宣称 QMI8658 提供医疗数据、GPS、磁力计或专业运动精度。

## 4. 功能范围与明确非目标

范围包括共享 I²C、时间/闹钟服务、BOOT/PWR 语义、电源状态、低频 IMU、抬腕、计步和 Activity 最小应用。非目标包括 SD/音频、手机同步、Wi-Fi/NTP 直连、医疗功能和未验证的深睡。

## 5. 分任务实施顺序

### Task 1：把 Touch 纳入共享 I²C 所有权

- [ ] **文件范围：** `Firefly/touch.h`、`I2cBusManager.*`、触摸输入适配和核心/契约测试。
- [ ] **预期失败：** 先增加测试或探针证明 TouchLib 仍直接操作 `Wire`，无法与受锁 RTC/PMU/IMU 形成同一事务边界。
- [ ] **最小实现：** 让触摸读写通过同一个管理器或单一硬件任务串行执行；锁内不调用 LVGL、不做长延时。
- [ ] **验证命令：** 运行目标契约、核心测试和主固件构建。
- [ ] **预期结果：** 当前树中没有绕过所有权的触摸访问；超时可诊断且不会永久占锁。

### Task 2：收敛时间与闹钟服务

- [ ] **文件范围：** `Firefly/FireflyAlarm.*`、RTC HAL、计划创建的 `services/TimeService.*`、`AlarmService.*`、时钟应用与测试。
- [ ] **预期失败：** 跨日、星期掩码、同一分钟去重、队列满、手动校时和 RTC 失败测试先失败。
- [ ] **最小实现：** 先内存时间快照和单闹钟事件，再迁移现有固定槽位、UI/持久化；事件成功入队后才更新去重记录。
- [ ] **验证命令：** 运行核心时间测试、Python 契约和主固件构建。
- [ ] **预期结果：** UI 只读快照/发命令，RTC 只经共享 I²C；NTP 保留为计划 6 输入。

### Task 3：收敛电源、按键与屏幕状态

- [ ] **文件范围：** PMU HAL、计划创建的 `PowerService.*`、输入状态机、现有 BOOT/PWR 路径和测试。
- [ ] **预期失败：** 去抖、短按/长按、低电拒绝、屏幕状态和失败保守测试先捕获现有分散逻辑。
- [ ] **最小实现：** 纯状态计算先行；电量未知时拒绝高功耗会话，极低电保存后安全关机，日志区分一瞥/熄屏/复位。
- [ ] **验证命令：** 运行状态测试、完整构建和当前板按键矩阵。
- [ ] **预期结果：** BOOT/PWR 语义确定，PMU 失败不显示虚假电量；真实浅睡仍关闭。

### Task 4：接入低频 IMU、抬腕、计步与 Activity

- [ ] **文件范围：** `LockedRegisterDevice.*`、计划创建的 `MotionService.*`、活动模型/页面、预览与测试。
- [ ] **预期失败：** 固定环形容量、冷却、静置误步、抬腕抑制和服务失败降级测试先失败。
- [ ] **最小实现：** 先只读设备身份和固定样本，再加入低频采样、轻量计步/抬腕；Activity 页面只读快照。
- [ ] **验证命令：** 运行运动测试、预览检查、主固件构建和真机采样探针。
- [ ] **预期结果：** IMU 不可用时隐藏/降级活动能力，触摸与传感器并发仍稳定。

### Task 5：建立并决定浅睡门槛

- [ ] **文件范围：** 生命周期、电源服务、唤醒适配和验证记录。
- [ ] **预期失败：** 任一按键、RTC、触摸或 IMU 唤醒源未达到规定成功率时，浅睡启用检查必须失败。
- [ ] **最小实现：** 明确 prepare/sleep/resume 清理顺序；只启用全部通过的唤醒源。
- [ ] **验证命令：** 自动状态测试加每个唤醒源独立真机循环。
- [ ] **预期结果：** 未全部通过时功能保持关闭并标记阻塞，不用软件模拟结果替代硬件证据。

## 6. 自动验证

运行 `python knowledge/validate_knowledge.py`、时间/电源/运动核心测试、`python -m unittest discover -s tests/python -v` 和完整主固件构建。预期固定容量、非法转换、队列满、I²C 超时与降级路径均有检查。

## 7. 真机验收

- [ ] 连续滑动与 RTC/PMU/IMU 访问并行运行至少 30 分钟，无触摸失效、卡屏、闪屏或复位。
- [ ] RTC 手动设置、掉电保持、跨日和闹钟触发/关闭在当前板通过。
- [ ] 电池、充电、低电与温度失败路径显示可信；记录功耗基线。
- [ ] IMU 静置 10 分钟、步行对比和抬腕误触有原始记录。
- [ ] 每个计划启用的唤醒源独立循环 20 次；任何失败都保持浅睡关闭。

## 8. 退出门槛与下一计划

共享 I²C 是硬前置；它与时间、电源、IMU 真机稳定后，计划 3 才能退出并进入计划 4。Activity 只有形成可调用服务、页面闭环和设备记录后才能从占位升级为当前已有。
