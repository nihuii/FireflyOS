# 计划 2A：UI Shell 缺口补全

## 1. 目标与当前状态

这是当前最高优先级执行项：先让系统面板在完整交互区域稳定上滑返回，再用日志和真机现象冻结 BOOT、一瞥、黑屏和唤醒基线。当前 `status_drag_cb` 只绑定面板、顶部状态栏和窄把手，面板内部子对象可能截获事件。

## 2. 知识库依据

- [02-UI Shell 与导航覆盖层](../../knowledge/02-UI-Shell与导航覆盖层.md)
- [04-电源、按键、触摸与 IMU](../../knowledge/04-电源按键触摸与IMU.md)
- [当前交接](../项目介绍-对话衔接版.md)

## 3. 前置条件与禁止事项

- 先记录当前面板打开/关闭位置、按压对象、释放/取消路径和 BOOT/息屏日志。
- 只修事件所有权和必要状态，不做视觉改版；需要视觉变化时先出预览。
- 不在事件回调外的后台任务访问 LVGL。
- 不启动后台 PMU、RTC、IMU 并发轮询，不顺带迁移 Touch/I²C。
- ROM/stub 上传错误单独归入 USB/端口链路，不当作应用崩溃。

## 4. 功能范围与明确非目标

范围是面板完整手势、控制/通知子页、BOOT 返回、一瞥/黑屏/唤醒日志和真机交互基线。非目标是共享 I²C、电源服务、浅睡、抬腕、媒体、无线与主题视觉重做。

## 5. 分任务实施顺序

### Task 1：建立可重复的面板事件失败检查

- [ ] **文件范围：** `Firefly/FireflyInteraction.cpp`、面板创建代码和 `tests/python/test_repository_contracts.py`。
- [ ] **预期失败：** 在滑杆、按钮、卡片和通知列表等子命中目标起手时，父面板收不到完整 pressed/pressing/released 或 press-lost 序列。
- [ ] **最小实现：** 先增加源码契约或最小事件探针，记录事件目标、当前 y 和拖动状态，不改变布局。
- [ ] **验证命令：** 运行目标 Python 契约并在真机复现至少三类子对象起手失败。
- [ ] **预期结果：** 测试因缺少统一捕获/冒泡规则而失败，真机日志能定位事件被截断的位置。

### Task 2：统一面板完整区域事件所有权

- [ ] **文件范围：** `Firefly/Firefly.ino` 的面板装配、`Firefly/FireflyInteraction.cpp` 的拖动状态机，必要时最小调整 UI Shell 接口。
- [ ] **预期失败：** 修复前子对象区域无法上滑、取消后 `is_dragging_notif` 残留或动画目标错误。
- [ ] **最小实现：** 使用一个覆盖完整面板的受控捕获层，或为全部交互子对象建立明确冒泡；保留点击/滑杆行为，并统一 pressed、pressing、released、press-lost 清理。
- [ ] **验证命令：** 运行契约、构建主固件，并在控制页和通知页各执行 20 次上滑。
- [ ] **预期结果：** 任意非冲突区域均可关闭面板；滑杆横向操作和按钮点击不被误判为上滑。

### Task 3：冻结 BOOT、一瞥与黑屏基线

- [ ] **文件范围：** `Firefly/FireflyInteraction.cpp` 的按键/屏幕状态路径和有界串口诊断。
- [ ] **预期失败：** 仅凭屏幕变黑无法区分进入 Glance、ScreenOff、预期熄屏或崩溃。
- [ ] **最小实现：** 为状态转换、触发源和主循环存活增加一次性/限频日志；不改变既定功耗策略。
- [ ] **验证命令：** 真机执行锁屏、桌面、应用、面板打开、闹钟覆盖等状态下的 BOOT/PWR 序列。
- [ ] **预期结果：** 每次黑屏都有可追踪状态与唤醒结果，崩溃/复位有独立证据。

## 6. 自动验证

运行 `python -m unittest tests.python.test_repository_contracts -v`、`powershell -ExecutionPolicy Bypass -File tools/verify_all.ps1` 和 `python knowledge/validate_knowledge.py`。预期事件契约、现有导航/层级契约及构建全部通过。

## 7. 真机验收

- [ ] 从面板背景、卡片、按钮附近、通知列表和滑杆外侧分别上滑，每类 20 次无卡死。
- [ ] 滑杆横向调整 20 次，数值变化正确且面板不误关闭。
- [ ] 控制页与通知页来回切换 20 次后仍可上滑关闭。
- [ ] BOOT/一瞥/黑屏/唤醒序列各 20 次，日志与屏幕行为一致且无复位。
- [ ] 连续操作期间触摸、动画和主循环无超过 250ms 的无反馈阻塞。

## 8. 退出门槛与下一计划

面板手势和 BOOT/息屏基线必须先取得当前真机证据。完成后回到计划 2 关闭 Gate B，再进入计划 3 的 Touch/I²C 统一；不能直接跳到后台硬件服务。
