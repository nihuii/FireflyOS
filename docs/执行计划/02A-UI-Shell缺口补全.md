# 计划 2A：UI Shell 缺口补全

> 适用范围：补全《02-UI-Shell与视觉系统.md》已发现但尚未形成真实运行闭环的功能。本文不改变已确认的视觉方向，不提前实现计划 3～6 的硬件业务能力。

## 1. 完成标准

- `UiShell` 的路由变化能够真正驱动锁屏、主屏、设置和应用占位页，而不只是修改导航栈。
- BOOT 短按、桌面滑动和应用入口共享同一套路由状态；全局页面层级由 Shell 统一管理。
- 控制中心与通知中心是面板容器内的两个同级页面，可互相切换；主要触控目标不小于 48 px。
- 控制中心具备音量、亮度、BLE、Wi-Fi、省电和锁屏入口；尚未进入后续计划的硬件能力明确显示为 UI 占位状态。
- 通知中心支持空状态、最多三条本地通知和一键清空。
- 锁屏显示真实的下一闹钟；状态刷新按修订号和本地控件值去重。
- 字体工具可从源码稳定收集系统字形，并与人工保留字形合并；在缺少授权字体时继续使用 LVGL 内置字体占位。
- 自动化测试、主程序编译和文档检查通过；真机触控、内存和 50 次循环压力测试保留为 Gate B 人工验收项。

## 2. 实施任务

### 2.1 Shell 路由与生命周期

1. 为 `UiShell` 增加路由回调、返回、状态同步及应用层前置接口。
2. 新增轻量 `AppShellScreen`，为尚未进入后续计划的应用提供一致的标题、状态说明和返回提示。
3. 将桌面应用点击、BOOT 短按、锁屏/主屏切换接入统一路由。
4. 用 `Screen::show/hide/refresh` 接管主屏、锁屏和息屏界面的可见性，移除业务代码中的全局层级抢占。

### 2.2 系统面板

1. 将 `ControlCenter` 改造成拥有独立根节点的页面，与 `NotificationCenter` 成为同级页面。
2. 调整音量与亮度控件为至少 48 px 高的触控目标。
3. 增加 BLE、Wi-Fi、省电、锁屏四个快捷入口；BLE/Wi-Fi 在计划 5/6 前只维护 UI 状态。
4. 为通知中心增加清空按钮和清空 API。
5. 由 `UiShell` 统一切换控制/通知页面。

### 2.3 数据闭环

1. 在时间刷新时调用闹钟调度器查询下一闹钟，并更新锁屏文案。
2. 控制中心使用系统状态修订号、音量和亮度共同判定是否需要重绘。
3. 保持本地数据优先，手机连接不成为以上功能的前置条件。

### 2.4 字体与验收工具

1. 新增可测试的源码字形收集脚本，输出排序稳定、去重后的 `system_glyphs.txt`。
2. 字体构建脚本在生成字体前自动运行字形收集。
3. 更新 Gate B 记录，区分已通过的软件验证与仍需开发板完成的人工验证。

## 3. 测试顺序

1. 先补充失败测试：Shell 接线约束、48 px 触控约束、下一闹钟接线、通知清空和字形收集。
2. 实现最小代码令新增测试通过。
3. 运行 `python -m unittest discover -s tests/python -v`。
4. 运行 `tools/verify_all.ps1`，验证核心库、主程序编译和文档一致性。
5. 在真机具备条件后按 Gate B 记录执行触控、圆角安全区、内存和 50 次循环测试。

## 4. 明确不在本次范围内

- BLE/Wi-Fi 的真实连接协议、Android 伴侣应用、天气和 OTA。
- 音频录制、文件管理、IMU 业务应用等计划 3～6 功能。
- 未取得授权的中文字库和正式角色美术；本阶段保留可替换占位资源与生成提示词。
