# 计划 6：Wi-Fi、天气、OTA 与发布验收

## 1. 目标与当前状态

当前 main 只有 Wi-Fi/OTA 能力枚举、天气/更新视觉占位和 32MB 双应用分区布局；没有 WifiService、NTP/天气服务、大文件传输、更新状态机、签名验证、首启确认、恢复出厂或 Release 闭锁。本计划按 NTP→认证配网→天气→传输→签名 OTA→首启回滚→恢复/发布的顺序开发。

## 2. 知识库依据

- [10-Wi-Fi、NTP 与天气](../../knowledge/10-WiFi-NTP与天气.md)
- [11-大文件传输](../../knowledge/11-大文件传输.md)
- [12-OTA 更新与首启回滚](../../knowledge/12-OTA更新与首启回滚.md)
- [13-诊断、恢复出厂与发布闭锁](../../knowledge/13-诊断恢复出厂与发布闭锁.md)

卡片 10、11、12 的唯一主要计划是计划 6；卡片 13 主要归计划 1，本计划使用其恢复和发布收口部分。

## 3. 前置条件与禁止事项

- Gate D 安全会话稳定，计划 4 已提供受管存储/租约，计划 3 已提供电源门控。
- Wi-Fi 是按用途租用的高功耗资源；所有成功、失败、超时和取消路径归还租约。
- 当前 app0/app1、otadata、FFat、coredump 布局只允许冻结和验证，不重新创建。
- 写入固件前完成签名验证，写入后验证摘要；不得把 SHA-256 当作来源认证。
- 生产信任锚和固定更新配置来自仓库外；缺失时 Release 必须阻塞且不留候选产物。

## 4. 功能范围与明确非目标

范围包括按需 Wi-Fi、认证配网、NTP、手机优先天气缓存、可选 HTTPS 适配、大文件临时会话、签名双槽 OTA、pending-verify、恢复出厂、有界诊断和发布闭锁。非目标包括常驻 Wi-Fi、云账户、公开固定凭据、BLE 大文件和绕过用户确认的更新。

## 5. 分任务实施顺序

### Task 1：实现单用途 Wi-Fi 与 NTP

- [ ] **文件范围：** 计划创建的 WifiService/NtpService、ResourceGovernor、PowerService、时间服务适配和测试。
- [ ] **预期失败：** Off/Connecting/Connected/Error、超时、取消、低电拒绝、租约泄漏和多用途冲突测试先失败。
- [ ] **最小实现：** 仅开放单一 NTP 用途，固定凭据/用途容量；NTP 只提交时间结果，由 TimeService 决定 RTC 写回。
- [ ] **验证命令：** 运行状态/租约测试、主固件构建和真实路由器连接/关射频测试。
- [ ] **预期结果：** 空闲后射频关闭，所有失败路径归还资源，响铃期间不强行校时。

### Task 2：加入认证配网与天气缓存

- [ ] **文件范围：** BLE 配网消息、WifiProvisioningService、WeatherService、Weather 页面、FFat 缓存、预览与测试。
- [ ] **预期失败：** 未认证凭据、用户拒绝、超长字段、过期缓存、异常数值、断网和低电测试先失败。
- [ ] **最小实现：** 凭据先暂存并由手表确认；天气先接手机快照，区分新鲜/陈旧/过期，之后才加有上限的 HTTPS 适配。
- [ ] **验证命令：** 运行配网/天气模型测试、预览、主固件与弱网真机测试。
- [ ] **预期结果：** 日志不含密码或完整 SSID；离线显示最近可信缓存并标记时间。

### Task 3：建立受认证大文件临时传输

- [ ] **文件范围：** BulkTransferService、临时传输适配、Android 上传组件、Storage/Wi-Fi 租约和测试，均为计划创建。
- [ ] **预期失败：** 非法路径、超长 header/body、声明长度不符、摘要不符、取消、拔卡、超时和重启测试先失败。
- [ ] **最小实现：** BLE 只协商 request ID、路径、长度、摘要和一次性 token；数据写受管 `.part`，校验后原子提交。
- [ ] **验证命令：** 运行路径/清理/摘要测试，并做小文件、最大文件、拔卡和网络中断真机传输。
- [ ] **预期结果：** 校验前目标模块看不到最终文件，任何失败都关闭句柄、删除临时文件并释放租约。

### Task 4：冻结分区并实现签名 OTA 状态机

- [ ] **文件范围：** `Firefly/partitions.csv`、`tests/python/test_build_configuration.py`、计划创建的 UpdateManifest/UpdateService、SD/HTTPS source、writer 和测试。
- [ ] **预期失败：** 分区重叠/不等大、产品/版本/尺寸/摘要/签名错误、低电、资源冲突、取消和写当前槽测试先失败。
- [ ] **最小实现：** 持续验证现有布局；canonical 清单和 ECDSA P-256 验签通过后，以固定块写非当前槽并复核摘要。先接 SD，再接 HTTPS。
- [ ] **验证命令：** 运行分区、清单、拒绝向量和内存 writer 测试，再做 SD 坏包/断电真机测试。
- [ ] **预期结果：** 双应用布局不被误称为 OTA 服务；未通过签名或门控时不开始写入。

### Task 5：实现 pending-verify 与真实回滚

- [ ] **文件范围：** 计划创建的 BootValidationService、生命周期、RTC/PMU/显示/触摸/NVS/UI 健康探针和测试。
- [ ] **预期失败：** 超时、看门狗、单项硬件失败、主 UI 未运行和重复启动测试先失败。
- [ ] **最小实现：** 固定期限内逐项确认；全部成功才标记有效，失败保持可回滚状态。
- [ ] **验证命令：** 运行状态测试，并在真机执行成功更新、坏固件、断电和首启失败矩阵。
- [ ] **预期结果：** 失败固件自动回到最近稳定槽，日志能说明未确认原因。

### Task 6：恢复出厂、诊断与 Release 闭锁

- [ ] **文件范围：** 数据 owner 清单、FactoryResetService、DiagnosticService、构建发布检查和恢复/更新预览。
- [ ] **预期失败：** generation 过期、重复确认、部分 owner 失败、越界 SD 路径、缺生产锚和镜像超限测试先失败。
- [ ] **最小实现：** 每个 owner 幂等清理；内部数据一次确认，SD 白名单二次确认；Release 缺任何生产输入立即失败并清理候选产物。
- [ ] **验证命令：** 运行恢复/发布测试、完整构建、候选尺寸检查和当前板恢复首启。
- [ ] **预期结果：** 不格式化整卡、不泄露密钥；测试信任锚不能生成 Release 候选。

## 6. 自动验证

运行 `python knowledge/validate_knowledge.py`、网络/天气/传输/清单/签名/恢复测试、`python -m unittest discover -s tests/python -v` 和完整构建。预期所有容量、超时、取消、租约、拒绝向量和发布缺料路径失败保守。

## 7. 真机验收

- [ ] 至少两种路由器环境验证连接、弱网、断网、空闲关射频与低电拒绝，并测量功耗。
- [ ] NTP、手机天气、离线缓存和 HTTPS 适配分别验证，不以单一成功替代其他用途。
- [ ] 大文件完成、取消、超时、拔卡、断电与最大尺寸传输均清理正确。
- [ ] OTA 成功、坏签名、坏摘要、写入中断、首启失败与回滚逐项留存日志。
- [ ] 恢复出厂后首启、SD 二次确认、24 小时长稳和 400mAh 代表性续航完成。

## 8. 退出门槛与下一计划

Gate E 只有在网络、传输、OTA、回滚、恢复、长稳、续航和生产输入闭锁全部有当前证据时关闭。缺生产信任锚、固定更新配置或真机回滚证据时状态为阻塞，不创建发布候选或标签。
