# FireflyOS 项目介绍

## 1. 项目目标

`FireflyOS` 是一个基于微雪 `ESP32-S3-Touch-AMOLED-2.06` 开发板、使用 `Arduino` 作为开发环境的手表式 UI/OS 项目。

项目主题是为《崩坏：星穹铁道》角色“流萤”设计一套轻量级、可交互、视觉风格统一的设备系统界面。

当前目标不是做一个完整通用操作系统，而是先完成：

- 锁屏 / 桌面 / 设置 / 息屏等核心页面
- 闹钟、电量、亮度、时间等常用系统功能
- 贴合圆角 AMOLED 屏幕的 UI 体验
- 在 ESP32-S3 资源限制下尽量保证流畅度

## 2. 开发板与硬件基础

开发板：`Waveshare ESP32-S3-Touch-AMOLED-2.06`

当前工程已经确认并使用到的主要硬件资源：

- 主控：`ESP32-S3`
- 屏幕：`2.06` 英寸 AMOLED，分辨率 `410 x 502`
- 屏幕驱动：`CO5300`
- 触摸：`FT3168`
- RTC：`PCF85063`
- 电源管理：`AXP2101`
- 板载按键：`BOOT`、`PWR`
- 可扩展能力：`Micro SD`、`QMI8658`、`ES8311`、`Wi-Fi`、`Bluetooth`

当前主工程中实际已经接入的外设能力主要有：

- 屏幕显示
- 触摸输入
- RTC 时间读写
- 电源/电池状态读取
- `BOOT` 去抖短按与 `AXP2101 PWR` 短按/长按事件
- `QMI8658` 加速度计与陀螺仪采样

## 3. 开发环境

- 开发框架：`Arduino`
- 图形库：`LVGL 8.3.11`
- 显示驱动库：`Arduino_GFX`
- 触摸库：`TouchLib`
- 传感器库：`SensorLib`
- 电源管理库：`XPowersLib`

注意：

- 官方资料中存在 `LVGL v9` 示例，但当前主工程 `Firefly` 实际基于 `LVGL v8.3.11`
- 后续新增功能时应优先沿用当前主工程的 `LVGL v8` 写法，避免直接混用 `v9` 接口

## 4. 工程目录说明

项目根目录主要结构如下：

- `Firefly/`
  - 主工程目录，当前实际开发重点
- `examples/`
  - 官方示例代码，用于参考板载功能接法和初始化流程
- `libraries/`
  - 本项目使用到的本地库；其中 `libraries/FireflyOS/` 是新增的模块化系统核心
- `image/`
  - 流萤相关图片资源，包括壁纸、息屏图、GIF 等
- `开发板资料/`
  - 开发板引脚定义、产品特性、硬件说明
- `开发原则.txt`
  - 当前项目开发时应遵守的原则

## 5. Firefly 主工程文件说明

`Firefly/` 目录中重要文件如下：

- `Firefly.ino`
  - 主入口，负责系统初始化与主要 UI 搭建
- `FireflyApp.h`
  - 全局对象、外设、UI 组件、函数声明集中头文件
- `FireflyState.cpp`
  - 全局状态与全局 UI 指针定义
- `FireflyInteraction.cpp`
  - 交互逻辑、状态切换、闹钟触发、电池刷新、息屏/唤醒逻辑
- `FireflyDisplay.cpp`
  - LVGL 显示刷新与触摸输入桥接
- `FireflyAlarm.h` / `FireflyAlarm.cpp`
  - 双闹钟数据结构、重复规则、下一次响铃计算
- `FireflyTheme.cpp`
  - 根据设置页壁纸自动采样主题色
- `LockWallpaper.*`
  - 锁屏与桌面壁纸资源
- `SettingsWallpaper.*`
  - 设置页壁纸资源
- `SleepIcons.*`
  - 息屏图片资源
- `pin_config.h`
  - 当前板级引脚定义
- `touch.h`
  - 触摸初始化与读数映射

### 5.1 模块化核心

`libraries/FireflyOS/src/firefly/` 当前按职责拆分为：

- `core/`：定长 `EventBus`、`StateStore`、能力注册、应用注册/管理、生命周期和资源仲裁。该目录不依赖 LVGL。
- `hal/`：不依赖 UI 的设备接口、共享 I2C 互斥管理器、包裹现有 RTC/PMU/CO5300 的 `LegacyBoardAdapter`，以及 QMI8658、ES8311 共用的受锁寄存器访问边界。

主工程仍保留原有全局硬件对象和页面函数，按模块逐步迁移，不进行高风险的一次性重写。新增代码优先通过值对象（如 `BatteryState`）向上层提供状态，硬件适配器不更新 LVGL 控件。

后台任务与 UI 的并发边界如下：

- 后台任务是系统事件的生产者，检测 `BOOT`、`PWR`、QMI8658 运动源和息屏时序。
- `EventBus` 是容量为 16 的有界队列，关键事件可替换队列中的刷新类事件。
- Arduino `loop()` 是唯一消费者，也是唯一执行 LVGL 页面动作的位置。
- 当前没有增加第二条 UI 执行链；后台任务创建失败时自动回退为 UI 主循环轮询。

### 5.2 UI Shell 与视觉系统

`libraries/FireflyOS/src/firefly/ui/` 已建立固定深度导航、主题令牌、组件工厂和常驻 UI Shell。全局界面分为应用、状态栏、系统面板和覆盖层四级；控制中心、通知中心以及 1–5 级覆盖层由 Shell 统一管理。

一瞥、锁屏和桌面已实现统一 `Screen` 生命周期。桌面从 `AppRegistry` 生成 3 × 2 分页入口，当前美术使用 LVGL Symbol 占位，正式图标可在不修改导航与触摸热区的情况下替换。

## 6. 当前已经实现的功能

### 6.1 系统主界面

已经具备一套基本可运行的系统界面：

- 锁屏页
- 桌面页
- 设置页
- 息屏页
- 控制中心下拉面板
- 充电提示覆盖层
- 闹钟提醒覆盖层

### 6.2 页面行为

当前页面切换逻辑包括：

- 锁屏页可上滑进入桌面
- 桌面页不能反向滑回锁屏
- 桌面当前保留应用图标层结构，方便后续继续扩展 app
- 桌面已登记 11 个分页入口；`Clock`、`Calendar`、`Tools`、`Activity` 和 `Settings` 已接通，其余入口是后续应用计划的路由/美术占位

### 6.3 设置页面

设置页已经拆分为多个独立页面：

- `Sound`
- `Alarm`
- `Time & Date`
- `Battery & Power`
- `Display & Sleep`

已实现的设置能力包括：

- 音量调节
- 屏幕亮度调节
- 自动息屏时间设置
- 手动修改系统时间
- 从 RTC 载入时间
- 查看电池/供电信息

### 6.4 闹钟系统

当前闹钟功能已经不是占位，而是独立的一套系统：

- 单独的 `Alarm` 页面
- 最多 `2` 个闹钟槽位
- 显示时间、重复日期、名称、启用状态
- 支持新增闹钟
- 支持编辑闹钟
- 支持设置铃声、重复规则、闹钟名称
- 页面顶部显示“下一个闹钟还有多久响”
- 到点后会触发闹钟覆盖层提醒
- 支持手动关闭闹钟提醒

### 6.5 时间系统

时间相关已经接通：

- 启动时尝试从 `PCF85063 RTC` 同步时间
- 设置页可手动改时间
- 支持从 RTC 重新载入时间
- 闹钟逻辑基于当前系统时间进行匹配

### 6.6 电池与充电

当前已实现：

- 电池电量显示
- 电池电压读取
- 系统电压读取
- 温度读取
- 充电状态读取
- 插电/充电时弹出充电覆盖层

### 6.7 息屏与黑屏

当前息屏逻辑已做成一套完整流程：

- 可从锁屏进入息屏界面
- 息屏界面显示流萤图片、时间、日期
- 进入息屏时按顺序轮播 4 张图片
- 息屏后延时进入黑屏
- `BOOT` 短按可从黑屏唤醒回息屏
- 黑屏唤醒不会切换到下一张图

### 6.8 视觉与资源

当前视觉层面已实现：

- 锁屏壁纸
- 桌面壁纸
- 设置页壁纸
- 息屏流萤图片
- 设置页自动壁纸取色主题

资源优化方面已实现：

- 多张全屏壁纸改为原生 `RGB565`
- 息屏图使用 PNG 原始字节交给 LVGL 解码
- 尽量减少运行时图片解码压力

### 6.9 核心应用与运动

计划 3 已完成的软件实现包括：

- `Clock`：时间、日期、下一闹钟、双闹钟摘要、倒计时和秒表
- `Calendar`：固定 42 格月历、月份切换和最多 8 条日程摘要缓存
- `Tools`：固定长度计算器和带电量/温度/60 秒限制的 AMOLED 手电筒
- `Activity`：QMI8658 本地计步、活动分钟、目标环和传感器降级状态
- 当天运动聚合每 15 分钟或进入息屏前持久化，不保存全天原始运动样本
- 设置页面通过固定命令队列把 RTC、闹钟、亮度、音量和自动息屏操作交给 UI 主循环执行
- LightSleep 已有 100/100 门禁和失败恢复生命周期，但当前门禁为 0/100，发布配置不会真正进入睡眠

活动数据明确为非医疗估算，不展示心率、血氧、睡眠分数或卡路里医疗结论。

### 6.10 性能优化

已做过的主要性能优化包括：

- `LV_IMG_CACHE_DEF_SIZE` 从 `1` 提升到 `2`
- LVGL draw buffer 目标从 `80` 行提升到 `120` 行
- 内存不足时自动回退到 `80` 行
- 滑动过程中隐藏桌面图标层
- 去掉桌面蒙版与阴影，减轻绘制压力
- 增加保守型双核后台任务方案
- 用 16 项有界 `EventBus` 替换后台位标志，避免后台核直接驱动页面

双核方案当前原则：

- UI / LVGL 仍保持单核访问
- 后台核仅负责事件检测与事件投递
- 后台核不直接调用 LVGL 接口
- 后台核不直接参与 UI 绘制
- 共享 I2C 的新适配路径通过带超时的 FreeRTOS mutex 串行化
- 当前 RTC、PMU、屏幕亮度与 QMI8658 运行时访问已迁移到 HAL；ES8311 后续只能通过受锁控制适配器访问寄存器
- 串口每 10 秒输出 Gate A 内存低水位、事件投递失败、桌面切换最大耗时和运动汇总诊断

## 7. 当前还没有真正集成到主系统的能力

虽然开发板支持很多外设，但以下能力目前还主要停留在官方示例或库可用阶段，尚未真正并入 `FireflyOS` 主系统：

- `Micro SD` 文件系统与媒体资源读取
- `ES8311` 音频编解码
- `I2S` 播放/录音链路
- `Wi-Fi`
- `Bluetooth`
- 天气、音乐、录音、文件、主题和诊断应用的实际业务页面（桌面入口已占位）

也就是说，当前主系统重点仍然是：

- UI 框架
- 系统页面
- 时间 / 闹钟 / 电量 / 息屏 等基础功能

## 8. 最近开发重点

最近一段时间主要集中在以下方向：

- 建立固定层级的 UI Shell、6 层有界导航栈和统一页面生命周期
- 将桌面迁移为 AppRegistry 驱动的 3 × 2 分页入口
- 拆分控制中心与最多 3 条摘要的通知中心
- 建立覆盖层优先级、中文字体子集脚本和 AI 美术资源替换清单
- 将时间、双闹钟、电源状态机和 BOOT/PWR 输入迁入服务层
- 接通 Clock、Calendar、Tools 与 Activity 真实页面
- 接入 QMI8658 HAL、32 项运动缓冲、轻量计步和抬腕事件
- 建立真实 LightSleep 的 100/100 唤醒门；门槛未完成前保持 ScreenOff
- 补齐倒计时/秒表交互、设置命令消费者、LightSleep 失败恢复、IMU 功耗策略和固定诊断计数
- 在没有中文字库时使用可显示的短英文标签，并保留中文说明和预览文档

## 9. 当前已知的开发注意事项

- 项目 UI 需要考虑 AMOLED 圆角屏安全区，右下角、右上角和底部控件容易被裁切
- 当前闹钟编辑页已经做过多轮圆角安全区微调，后续再改时应优先微调常量，不建议随意重写整体布局
- 当前主工程明显偏向 `LVGL v8`，新功能应尽量沿用已有风格和接口
- 项目强调“轻量、流畅、低资源占用”，新增功能时要尽量避免引入高成本渲染

## 10. 开发原则

当前项目约定的开发原则是：

- 优先采用更省系统资源、响应更快、不会明显影响流畅度的方案
- 保持模块化设计，避免高耦合
- 如果要更深入利用双核，默认需要先确认复杂度和风险
- 功能更新后同步更新说明文档

## 11. 如果要继续开发，建议优先顺序

建议后续优先级如下：

1. 完成计划 3 的 RTC、按键、计步、抬腕和续航真机记录
2. 在 BOOT、PWR、RTC 唤醒全部达到 100/100 后再评估启用 LightSleep
3. 校准 QMI8658 计步阈值并记录至少 3000 步参考对比
4. 再进入 SD、音频或其他应用阶段
5. 最后考虑联网增强能力

原因是当前主系统骨架已经形成，先把现有交互和视觉打磨稳定，收益最高。

## 12. 当前项目一句话概括

`FireflyOS` 当前已具备可编译运行的流萤主题手表 UI Shell，以及时间、双闹钟、日历、工具、电源状态和 QMI8658 活动功能的软件实现；计划 3 的专项真机精度、唤醒与续航验收仍待完成。
